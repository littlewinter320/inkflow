# 墨流 0.5.3 功能更新计划

## 概要

本次 0.5.3 围绕七项体验改进：Writer 创意分身（零依据构思不做验证）、对话消息复制/回退/重跑、语音输入三修（JSON 转自然语言、停止后只填输入框、边听边出字）、Coordinator 软化并接入墨宝人设、智能提示词预测（取代固定快捷按钮、可在设置关闭）。所有改动不改变四个正式 Agent 的边界：chat 由 Coordinator 路由直接回复，ideate 是 Writer 的一次"灵感分身"调用（不写正文、不入正史、不做证据核验）。

### 1. terminal_session.py —— 路由软化 + chat/ideate 分支

- **TERMINAL_ROUTER_SYSTEM**（L21-84）追加两段：
  - 墨宝口吻：conversation_reply 一律以"墨宝"身份说话（内嵌 MOBAO_PERSONA 要点：亲切俏皮有分寸、闲聊像朋友、工作简洁、可轻带创作邀请不强推、不超过三句话）。
  - 新 action 语义：
    - `chat`：寒暄、闲聊、情绪表达、与创作无关的日常提问（"晚上好""我该怎么称呼你"），或用户明显只想聊天时使用。conversation_reply 直接完整回应，不进工作流、不说跑题、不催干活。
    - `ideate`：用户要从零构思、要灵感/点子/天马行空方案（如"帮我想几个故事点子"），且没有正史或规划依据可查。明确要求出点子时 authorization=approved。
  - 轻量会话规则区（L75-84）补充：闲聊优先 chat；讨论创作方案仍是 discuss；要具体点子才是 ideate。

  - `elif intent.action == "chat":` → `response = {"reply": intent.conversation_reply.strip() or "我在呢。想聊点什么，或者继续你的故事都可以。"}`（单次路由调用即出回复，不加第二次模型调用）
  - `elif intent.action == "ideate":` → `response = await self.engine.brainstorm(project.root, text, packet)`
- **_dispatch() 门禁** L930-934：豁免条件追加 `and intent.action != "chat"`（chat 不要求 approved；ideate 保持要求 approved，因为要花一次 Writer 调用）

### 2. engine.py —— Writer 灵感分身 brainstorm

新增方法（放在现有 provider 调用方法附近）：

```python
async def brainstorm(self, root: Path, prompt: str, packet: ContextPacket) -> dict[str, Any]:
    # Writer 灵感分身：无依据构思，不做证据核验、不写正文、不入正史
    result = await self.provider.generate_json(
        system_prompt=WRITER_IDEATE_SYSTEM,
        user_prompt=用户消息 + 最近对话上下文（取 packet 中最近对话 section）,
        output_model=CreativeBrainstorm,
        effort="low", max_tokens=2400, thinking=False,
        agent_role="writer",
        timeout_seconds=min(self.settings.request_timeout_seconds, 120.0),
    )
    return {"reply": result.data.reply, "model": result.model,
            "next_action": "选中哪个方向告诉我；确认后再进入正式规划流程。"}
```

- WRITER_IDEATE_SYSTEM from .prompts import
- 上下文直接用 `packet.to_markdown()` 的最近对话段（或整包截断到 ~6000 字），不新建检索

### 5. voiceRecording.ts —— snapshot 边听边出字

`LocalWavRecorder` 新增：

```typescript
snapshot(): Uint8Array {  // 用当前已积累的 chunks 编码 WAV，不停止录音
  const samples = new Float32Array(this.length);
  let offset = 0;
  for (const chunk of this.chunks) { samples.set(chunk, offset); offset += chunk.length; }
  return encodeMonoWav(samples, this.context.sampleRate);
}
```

JS 单线程，编码期间 onaudioprocess 不会并发写 chunks，安全。

## 决策与假设

1. chat 不加第二次模型调用：路由调用本身产出墨宝口吻回复，省 token 且延迟低。
2. ideate 要求 authorization=approved（与 write_draft 一致），因为要花一次 Writer 调用；闲聊式"我在想要写什么"仍走 chat/discuss。
3. 对话回退是纯前端消息截断，不动项目数据；小说正史回退仍走引擎 checkpoint 流程，两者不混用。
4. 语音停止后只填输入框（voice_auto_send 默认已是 False，设置开关保留给需要的用户）。
5. 智能提示词点击=直接发送（沿用现有快捷按钮交互）；关闭开关=隐藏 quick-row。
6. 不改 Agent 数量与边界：ideate 是 Writer 的受控分身调用（agent_role="writer"，Trace 可审计），不是第五个 Agent。
