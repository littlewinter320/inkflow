# 墨流（InkFlow）发布说明 · 0.4.0

0.4.0 重新设计了桌面端与 VS Code 中的人机协作体验：用户可以直接说目标、看见当前执行步骤、只修改锁定的文字，并让墨宝用不同动作反馈状态。正式小说 Agent 仍只有 Writer、Reviewer、Memory Keeper 三个，墨宝只是界面伙伴。

## 用户可见变化

- 墨宝增加待机、招呼、阅读、思考、等待、完成与休息状态；侧栏提供“打招呼、读选区、想一想、鼓励我、休息”互动。
- 对话答复默认按 10 字/秒逐字淡入，可一键立即显示；系统开启“减少动态效果”时自动关闭动画。
- 执行中显示实时步骤；完成后可展开公开判断摘要、证据和安全过滤后的详情，不展示或保存供应商原始思维链。
- VS Code 支持工作区级自定义提示预设，并内置续写体检、场景推进、对白声线和章末钩子四个快捷预设。
- 选中未验收章节草稿的一部分后，可以只保存批注，也可以让 Writer 只生成该选区的替换内容。确定性编排器负责拼回正文，旧稿进入版本记录，审查状态随新版本失效。
- 桌面端去掉选区操作的系统输入框，改为可预览原文、使用快捷意见、选择批注或局部修订的专用面板。
- 修复 VS Code/Monaco 与 Python 对 emoji 等 Unicode 字符计数不同导致的选区错位问题。

## 写作专业性

规划、正文与审查提示增加场景状态转移检查：每个场景明确进入状态、压力、选择和状态变化；上下文证据不足时保留不确定性，不把猜测写成正史。Reviewer 会检查不可能的时间、因果与人物知识跳跃。

## 数据与升级影响

- 不增加第四个小说 Agent，不改变三者职责边界。
- 不迁移 `.inkflow/inkflow.db`，不改变用户可见小说目录结构。
- 局部修订使用既有 `.inkflow/studio.db` 版本和批注能力；只对未验收草稿直接生效。
- 已验收正文仍必须先预览影响、创建检查点并确认后，才能走分支式回改流程。

## 已知边界

- 目前发布包的内置引擎仍以 Windows x64 为主；其他系统可从源码运行 Python 引擎。
- “查看思考”显示的是公开判断摘要、依据和工具状态，不是模型私有的逐步思维链。
