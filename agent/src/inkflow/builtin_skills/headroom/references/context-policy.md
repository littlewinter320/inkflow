# 墨流上下文取材与余量标准

用途：解释和安排当前输入，不代替Provider的真实输入上限检查。不安装Headroom代理、下载压缩模型、改供应商或承诺上游基准的节省比例。

## 预算口径

每个角色有自己的常用取材量和最大上下文容量。实际完整输入还包括应用合同、已装技能、Schema、历史及资料，最终受角色容量、模型总窗口、预留输出和传输余量共同约束。缓存命中输入仍占上下文容量。

context.inspect读取的是冻结设置，不是最终实报tokens。供应商没有回报的输入、缓存或费用保持未知，不能按零算。

## 取材顺序

1. 当前作者硬要求、角色职责、输出Schema和原任务范围保留。
2. 当前判断必需的同版原文、事实与来源身份保留；有证据不足先沿已有检索补读。
3. 目录先给名称和用途，只有实际当步匹配的技能正文进入模型；细则按角色与步骤引用。
4. 可选经验、示例和诊断按相关性保留，不能挤掉必要正文。
5. 旧候选、旧讨论和失效索引保持身份，不能继续赋权或作为新正史。

## 持续会话

复用已有SessionContext的自然任务边界与版本校验。冻结文件稳定排序，技能正文不夹运行时间、任务ID或瞬时统计，保护可复用前缀。用户改文件影响新任务，旧任务读原技能快照。

现有整理没有产生减量时保留原前缀。不能声称任意语义摘要完全无损，也不能用“压缩过”豁免缺原文；完整必要材料仍放不下时明确停在原预算门禁。

## 命中率与费用怎样看

- 检索命中：是否取到当前问题相关的正确版本。
- 采用正确性：模型是否正确使用所取资料，需要正文和审核证据证明。
- 供应商缓存：实际usage报告中的cached input，不能从本地前缀相同推断实际命中。
- 成本：同口径任务的输入、缓存输入、输出、调用次数、实际耗时及合格产物费用。失败、未知用量与重试分开记录。

减少一次无必要调用通常有直接成本意义；增加大段技能来追求缓存比例可能反而增费。未做真实对照前只报告实现和本地估算，不宣称节省了百分之多少。
