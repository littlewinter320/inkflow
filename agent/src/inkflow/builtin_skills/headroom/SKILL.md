# 上下文余量管理

这是墨流对Headroom“按内容选择、保留原件、需要时回读”思路的适配，不是安装第三方代理、压缩模型或新供应商。

## 触发与边界

主动点名@headroom，或说“使用上下文余量管理技能”时使用；默认不被动运行。工具只读本角色实际设置，不能让Skill提高设置、扩大窗口或删硬材料。来源不足时补读，容量不足时交明确缺口。

## 步骤、输入与输出

| 部分 | 输入 | 做法 | 输出 |
| --- | --- | --- | --- |
| 读容量 | 冻结任务与实际角色 | 必调scripts/inspect.json映射的context.inspect | 常用取材量和最大容量的真实设置回执 |
| 分材料 | 当前硬要求、必要原文、可选经验 | 读[取材标准](references/context-policy.md)，先保证判断所需原件 | 必留项与可选方法说明 |
| 按需装入 | 当前技能及引用 | 只读本步骤和责任匹配的入口与reference，不一次装整个技能库 | 实际装入清单与资源哈希 |
| 沿原边界整理 | 现有持续会话与版本记录 | 沿SessionContext自然边界整理，保留同版来源与未完成交接 | 原引擎回执；整理无收益时保留原前缀 |
| 交缺口 | 实际预算或来源问题 | 明确缺什么及下一步，停止本次无法成立的步骤 | 作者能读懂的原因，不伪造已优化收益 |

缓存命中仍占上下文。技能工具读取的容量不是最终完整输入计数，最终由Provider连同系统规则、Schema、历史和资料核算；未测量的节省不能报告为实际收益。

## 完成与不能完成时

工具读数、必要材料和原Provider输入检查均有回执才可说明本次容量状态；不能只读出一个设置值就说已经优化。必要资料仍装不下时交具体缺口，不能自动提容量、删证据或重发请求。取消与恢复沿原任务、原预算和原技能快照，未知用量单列。经验只辅助后续选择，内容修改先给候选，不后台试跑。

作者可在设置阅读[完整流程说明](references/process.md)，区分容量、检索命中、缓存命中及真实采用。
