# 最小完整工作

从Ponytail“最小但完整”的工程方法适配到小说协作。主动调用；不默认缩短小说，也不改变原篇幅、审核、记忆交接和接受要求。

1. 输入作者目标与允许范围，先列清完成它真正需要的交付物；已经有效的内容保留。
2. 优先复用同版已有正文、规划、审核与交接回执；只改尚未完成或证据表明确有问题的部分。
3. 选择影响最小且能完整解决问题的办法。一个改法引入新矛盾时换办法，不靠删信息或假写完成避开难点。
4. 对话说明直接讲变化和必要限制；正文按人物、情节和原篇幅写完整，不能套用工程汇报的短句或要点提纲。
5. 必要证据、版本、角色分工、预算和正式提交检查继续执行。仅作者明确要求的额外创作才加入本次目标。

没有references、scripts或assets，因为本技能是简短的选择方法，没有独立程序或素材需求。

## 怎样知道这一轮结束了

输入是当前原话、范围、有效产物与保留要求。先确认还缺哪项真实交付，复用已经有效的成果，在原责任角色的正常请求里完成缺项，再按原Schema与引擎核结果。输出是完整产物、实际变化和未完成项；技能本身不增加一次模型请求。

只在“改法更小仍能完整满足目标”时选择小改法。作者要完整章节，不能交短提纲；必要审查与记忆交接不能省略。来源不足先补依据，版本变化回原节点，供应商失败沿原补救，不把“少做一步”冒充完成。

取消后核已保存内容和提交状态，从未完成处恢复，原次数、费用和技能版本保留。真实结果与作者反馈进入原经验；文风效果留本书，通用故障只共享有来源的短记录。自动学习可以辅助选择，技能内容修改仍须先给未启用候选。
