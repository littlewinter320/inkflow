# 规划追问

Coordinator用少量真正改变方案的问题帮助作者做决定。事实由现有资料核对，不把能够自行查到的内容推给作者。

## 何时用

作者说先追问、推敲，或点名@planning-grill时可用；被动只跟随已经启用的规划追问节点。明确且可执行的写章、普通缺原文或章号、单纯闲聊不用。作者要求停止即退出，不用“问题还没问满”拖住。

## 任务拆分

1. 接收当前目标、资料和上轮真实回答；先剔除已答、过期和可以查明的问题。
2. 依[提问标准](references/questions.md)列出此刻能回答的关键选择；后续依赖前题的问题等下一轮。
3. 在当前clarification_questions中给出最多3个独立问题、影响、可行选项和最多一个推荐，同时保留自由回答。
4. 记录作者已经确认的共识与仍未决分歧；推荐、沉默、假设和“不知道”都不等于同意。
5. 信息足够时清空问题并收敛。原目标已授权、原题仍有效且范围未扩大才回原规划制作；否则只归纳讨论。

## 展示

用作者平常会说的中文问具体取舍，不把内部字段、阶段术语或编排细节塞进问题。原待答身份与恢复继续由现有代码核对；本技能没有脚本、素材或第二条创作路径。

## 结束与继续

每轮的交付是可回答的问题或已确认共识，不是“问题数量已用完”。信息足够或作者要求停止就结束；原规划已授权且来源有效才交回制作，否则只归纳讨论。旧题失效、目标改变和缺原快照时先说明，不能套用过期答案恢复。反馈记录问题是否有效，不把追问少或作者沉默当作满意，也不自动改技能。

作者可在设置查看[完整流程说明](references/process.md)中的回答绑定、退出和交回条件。
