# 小说分层规划：从作者目标到生效规划

## 使用前先确认什么

本技能处理全书大纲、卷细纲、近期章节安排及其审核。作者明确要求修改哪一层，就从哪一层开始；“解释细纲是什么”只是对话，不进入生成。先接受过去已经发生的事实，再设计尚未发生的未来。

主责是Writer。Coordinator确认目标、层级、范围和保留项；当前协作模式分派的Editor或Reviewer审核；原规划引擎完成版本校验、对齐和发布。任何一位角色说“完成了”，都不能替代发布回执。

## 1. 收束目标与允许范围

输入：作者原话、已经确认的选择、当前生效规划、目标章段以及不许改动的部分。
操作：区分改故事方向、改事件因果和改逐章安排。能从本书资料查到的事实自行核对；只有会改变方案的未决取舍才询问作者。
输出：这次要改的层级、起止范围、必须保留的事实、待确认选择。没有生成授权时只交讨论结果。
验收：本次目标和章段能唯一确定，不能把单层改动扩成全书重做。
失败交接：保留已有候选，向Coordinator指出具体缺项，不用生成更多层级填补歧义。
展示：说清“接下来哪段故事要怎样变化”，不只展示内部操作名。

## 2. 建立有来源的故事起点

输入：已接受前史、上层有效规划、人物知道什么、关键物件终态和真实承诺定义。
操作：逐项核对涉及过去的断言。规划中的“将会”不能当作“已经”；人物的猜测与客观发生分开。
输出：可沿用的起点、有效上层约束、确实缺少的来源。仅选取当前规划范围需要的资料。
验收：关键人物、物件和既往事件能追到实际来源；没有材料就明确未知。
失败交接：缺必要原文先沿已有来源入口补读；查不到则保留缺口，不能凭空补过去。

## 3. Writer制作当前层候选

输入：已核起点、人物目标、阻力、代价、当前层结构以及作者的保留要求。
操作：大纲交代主线与人物变化；卷细纲安排相互导致的事件；近期规划交代每章动作及后果。同一线索换纸张或换地点却不改变局面，不算新的推进。
输出：当步Schema要求的规划候选；每项承诺保留真实ID、触发条件、完成条件和具体推进动作。
验收：本层职责完整，前后因果可执行，未夹入正文、未扩大章段。
展示：先说候选改变了哪些选择、风险或结局，再列仍未解决的取舍。

## 4. 独立审核、定点修补与对齐

输入：候选原版、相同来源版本、原任务要求、审核分工。
操作：审核只阻断可定位的过去事实冲突、关键因果缺失和明确任务未覆盖。普通留白、尚未到揭晓点或合理未来调整不能直接判错。Writer只修有据问题及必要衔接。
输出：审核结论、双方原句、最小修订要求和修后候选。承诺对齐仍用同一合同，不改条件来制造“完成”。
验收：原程序核引文、来源和结构；修过的候选必须重新满足相应检查。
失败交接：意见证据不成立先回审核角色核实；来源变化回对应层，不重放有效的生成步骤。

## 5. 发布、恢复与后续采用

输入：已通过的当前候选、发布权限、真实来源和事务状态。
操作：原引擎发布并同步有效规划。发布了一半时按原事务续接，不能把部分文件当作完整生效结果；已接受正文不随规划重写。
输出：区分候选已保存、审核已通过、发布未完成和规划已生效。
验收：有效版本和必要投影一致，后续写作只采用已经生效的版本。
失败交接：取消、错版、权限不足或发布异常保留候选和断点，从未完成环节恢复，原预算和原技能版本继续保留。

## 使用结果怎样进入学习

真实流程图、技能内容版本、任务结果及模型用量进入原有经验与账本。规划质量和作者反馈留本书；通用工具故障与调用观察可形成有来源的个人参考。失败不会自动证明技能写错。需要改技能时先形成建议和未启用候选，由作者启用后只影响新任务。
