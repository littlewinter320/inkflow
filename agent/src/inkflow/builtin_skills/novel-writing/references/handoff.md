# 正文交稿与附件交接

## 输入

本版完整正文、当前授权、已有承诺、实际提供的设定合集与输出Schema。缺少某项不编造其ID、版本或原句。

## 场景、篇幅与停点

- **场景接力**：把前一场留下的行动结果、信息、情绪或代价带进下一场，让它改变人物这次能做什么。换时间、地点或视角时尽早给必要的定位。用场景展开关键选择和后果，用简短叙述跨过读者能推知的过程。场景的开法、顺序和长度随功能调整。
- **篇幅安排**：按本次正文字数范围给关键场景分配篇幅，预留本章决定、结果及末场所需空间。偏短优先写出缺失的尝试、判断、阻力或后果；偏长先合并同义解释和重复过场。修订限本次授权范围，程序以交付正文实计。
- **普通章末**：先写清本章得到的结果或阶段进展，再选停在决定、揭示、代价、具体风险或自然余味。钩子以实写动作或信息为锚，读者能说清接下来想知道什么；承接前章钩子时用行动、部分答案或新的影响回应。只有章节概述或预填的钩子标签时，仍以实际停点判断期待。
- **篇章或卷末**：按作者要求或有效上层规划确定收束范围。让阶段矛盾有实际结果，给关键选择留出后果和人物反应。若还要续写，用结果造成的新处境接出下一篇。近期规划的最后一章只标记规划窗口的边界。
- **全书终章**：按本次有效收尾要求，用正文回应主线、关键承诺与人物归宿，最后一幕落在事情结束后的状态。可以用前文动作、场所或物件作呼应，让其意义随人物改变。作者明确保留的开放处写清可确定的结果与边界，预计回应留空。

## 正文与公开说明

- title单列，content只放完整正文；正文没有工作标题、字数统计、审查报告或技能清单。
- decision_summary只写必要的公开创作决定，不输出隐藏推理或复制整章。
- hook_note定位本版实际停点，说明已写清的事实及有意留白。有待答问题时再写读者期待和预计回应范围。自然收束可以只交代结果或余味。
- annotations最多8条，通常少量即可：new_fact是本章候选事实，interpretation是视角、谎言或传闻解释，future是尚未发生安排，unknown是未决定。前两类有本版连续quote，未来安排只交必要前提和公开因果，不写未来正文。
- 只有作者明确精修或场景蓝图时才展开scene_blueprint；普通草稿留空，不为了填表造场景。

## 设定提案

Writer只提出当前正文引入或变化的参考候选。对应合集有记录时沿record_id和expected_revision更新，首次有据出现才建档；没有变化或未说明字段不填。合集为空不是编造资料的理由，也不是忽略实际新增对象的理由。未来设想、人物信念、传闻与客观发生保持身份。

## 承诺交接

有真实规划合同才在promise_work中按thread_id记实际plant、advance、payoff或delay及正文quote、理由。未执行说明原因，不因预计章号到了写成已兑现；不以Writer声明替代memory_owner逐条核验。

## 角色和版本

Writer交稿不等于审核通过；正文通过不等于附件全通过；审核通过不等于正式接受。修稿后所有引用与hook_note改用新版，旧说明不能证明新正文。格式、引文和正式提交仍由原Schema、审核与引擎检查。

# 独立场景的篇幅与范围

独立练笔按作者这次的场景目标和篇幅交付，不套本书单章目标。短场景围绕一个当下行动和必要的反应展开，少添另一段开场、支线或尾声；不要把“约几百字”扩成一章。交稿前在原请求中粗核篇幅，明显偏长就压去无独立作用的重复，保留核心信息和作者明确要求，不另发一次计数或润色模型请求。实际篇幅是否符合要求仍须看产物，不能在说明里自行写成已达标。
