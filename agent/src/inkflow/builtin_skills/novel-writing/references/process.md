# 小说正文写作：从写作目标到可交接草稿

## 使用边界与责任

只有已经获准写某章或独立场景，Writer才进入本技能。“看看第67章”不等于重写；只写草稿也不包含审核、改稿和接受。Coordinator协调，Writer写作，审核和记忆由当前模式的责任角色承担，正式接受由引擎核验。

## 1. 接任务，确定这次要写什么

输入：作者原话、章号或独立场景目标、篇幅、视角、当前执行卡、保留项和禁止项。
操作：提取本次应发生的核心结果、人物处境与终止位置。已有同版草稿和完成回执先核对，不把“继续”当成重新起草。
输出：明确的一章或一个场景的写作目标。缺少决定性目标时由Coordinator只问必要问题。
验收：范围和交付类型一致；独立场景不能进入章节接受链。
展示：公开说明本次范围与实际进度，不复述整本书，也不展示隐藏思考。

## 2. 衔接人物、物件与前文

输入：必要前文、有效规划、设定和人物认知来源。
操作：核清场景入口处谁在场、谁知道什么、关键物件在哪里、上一场行动造成什么后果。作者样稿和偏好指导写法，不能覆盖已接受事实。
输出：可用的入口状态与尚缺的必要原文。
验收：关键行动有因，人物知道消息有途径；摘要不足时沿原来源补读，不能假设已经读过全书。
失败交接：必要资料装不下或来源缺失时报告具体缺口，不自行删硬材料、扩大上下文或改供应商。

## 3. 写成可读场景

输入：入口状态、人物目标、新压力、作者声音与本书要求。
操作：把观察、判断、行动与后果接起来。对白体现人物关系与实际目的；标点、内心、长短句按语境使用，不强凑冲突、反转、金句或固定段数。
输出：完整连贯的正文。标题、正文和公开交稿说明放各自字段。
验收：正文不夹字数、模型、审核、技能和任务说明；篇幅与场景范围按原任务，不能借润色缩短独立信息。
失败交接：输出中断或结构不合法先核真实返回与已存产物，原Provider的补救有回执，不能自动重写已保存正文。

## 4. 顺读并交候选附件

输入：同版完整正文、实际发生的设定和承诺变化。
操作：核物件去向、人物知情、时序、指代、因果和开场结尾；公开说明讲创作决定，hook_note等按真实当前Schema填写。未来打算与正文已发生分开。
输出：正文候选、必要交接字段、未解决问题。独立练笔保存在独立场景候选位置，不替换章节。
验收：原结构检查、版本和来源检查通过才保存对应产物；Writer不能批准自己的稿件。
展示：先交正文，必要说明另放专用区域；“已保存草稿”不写成“已收进正史”。

## 5. 按原目标选择审核、修补或结束

只写草稿：草稿保存后结束，不能因为流程图里有审核节点就执行。
写作并审核：责任角色核当前版本；有据且获准的问题交定点改稿，再审新版。通过的同版结果复用。
写作并接受：只有原目标明确含接受、审核和记忆前提满足时，原引擎才可正式接受。
必要分支按条件执行，原修订次数和费用沿任务保留。unknown表示缺证或待决定，不等于Writer必须改；已经完成的步骤不重放。

## 6. 中断恢复与学习闭环

输入：原任务、原技能快照、已存正文、各角色回执、剩余预算及当前来源。
操作：先核已经完成到哪一步和是否已正式提交，再续未完成节点。迟到输出不能覆盖后来版本；旧快照缺失不能拿当前设置补齐。
输出：可恢复断点或明确缺口，已有有效产物保留。
真实结果、调用、格式补正和作者反馈进入原经验库。自动学习辅助后续选择，不能把沉默当满意，不自动修改正文、技能或接受权限。
