# 定点改稿：从明确问题到可核验新版

## 触发条件与落稿边界

作者明确要求改某段，或原流程有当前版有据修订意见，才允许Writer进入。只审查、只提建议或只说“看看”不授权落稿。选区修订是实际替换当前草稿的业务操作，不能称为“只给候选”；如只想看方案，应保持讨论或另交独立场景候选。

## 1. 锁原版、定位与保留项

输入：当前正文及版本、唯一定位原句、作者要求、审核依据和不可改部分。
操作：确认选区在当前草稿中唯一匹配，或确定有据问题涉及的最小段落。已接受正文沿专门版本与权限入口，不套用草稿直接替换。
输出：允许替换范围、需保留事实、定位不清的缺项。
验收：原文、版本和范围一致；找不到不猜另一版，不用模糊指代扩大到整章。
失败交接：返回准确需要的原句或章段，保留当前正文。

## 2. 决定先审后改还是先改后审

作者要求先审核：先拿同版有据问题，再决定修哪里。
作者已经明确指定改法：按当前授权先改，之后需要的审核仍核新版。
资料未定或审核指控无依据：先回核依据，不交Writer猜剧情。unknown不是自动修订指令。
输出：当前动作顺序和可执行问题。编排只用登记工具，不增加一次选技能调用。
验收：顺序来自本次意图与原权限，不能被技能文件改成自动接受。

## 3. Writer作最小有效替换

输入：原段、邻接语境、真实问题、允许范围。
操作：按事实、因果、表达或篇幅分支选择改法；必要衔接可以调整，独立信息、人物声音与未授权段落保留。删掉一个指代后必须检查后文是否还引用它。
输出：当步Schema要求的局部替换、增补计划或完整修订稿。不能自行改换输出类型。
验收：原程序核匹配位置、范围、结构和来源；有模型回复不等于已保存。
展示：正文和修改说明分开，说明具体改了什么，不用“已优化”代替变化。

## 4. 对照与新版复核

输入：修前修后正文、同一保留清单、当前审核范围。
操作：核否定、确定程度、人物知情、物件状态、时序和前后指代；原来需要修的一项必须有明确处理结果。
输出：新版来源与版本、仍未解决问题、必要审核结果。
验收：旧版通过不能签新版。表达改善不能引入事实改动；普通建议不能被自动执行。
失败交接：越界或错版由程序拒绝，回到对应来源或Writer节点，不覆盖用户后来的改稿。

## 5. 条件修补、结束与恢复

只改稿的任务在保存相应结果后结束；带复审才执行复审；带接受也须当前全部前提满足。
后续修补仅由当前版有据问题触发，受原修订轮次和预算约束。通过或不需要修时跳过，不能为了把流程走满继续生成。
中断先查已保存版本和已完成回执，保留有效结果，从缺失步骤继续，不把上轮Writer成功返回当成新问题已修好。

## 使用反馈进入闭环

记录具体范围、实际产物、是否越界、格式补正、审核结果与调用成本；效果和文风反馈只在本书。失败先分清来源、程序、供应商和技能方法，再形成有来源的改进建议。技能内容的修改仍先交未启用候选，不能后台直接换掉正在使用的版本。
