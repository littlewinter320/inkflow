# 定点改稿

保留已经成立的故事，修本次真正的问题。Writer执行，审核角色提供依据，引擎核对替换范围、版本与后续接受。

## 可执行流程

本技能为混合类型，scripts/workflow.json按原任务选择先审后改或先改后审。后续补救只由当前版本的有据问题触发，受原修订轮次和预算约束；通过或已完成项复用。单章展开原工具图，批次保留原整体入口，不靠重新选择流程增加模型请求。

## 触发与不触发

主动请求改某段、按有据意见修稿、压缩或补足篇幅，以及引擎进入对应修订节点时使用。单纯审查或建议不产生落稿许可；已接受稿必须沿原专门权限。只知道“像AI”而没有具体问题时先定位，不机械换词。

## 工作顺序

1. **锁定。** 输入当前正文、版本、定位原句与保留要求；确认原句确实存在。输出本次可改范围，无法匹配交回源头，不猜另一版。
2. **辨别。** 对照作者要求、原审核证据和正文，判断是事实、因果、表达还是资料误判。意见无依据或与正史冲突时说明，不先改稿求通过。
3. **修订。** 从影响最小的有效办法开始；必要时改相邻衔接，不借机重写整章、换视角或提前揭密。具体分支读[操作标准](references/operations.md)。
4. **顺读。** 核对修前修后信息、否定、归因、人物知识、关键物件状态及后果；不能为消除一个问题制造另一个。处理每条阻断意见并保留未解决项。
5. **交付。** 按当前Schema给局部替换、补足计划或完整修订稿；不能自选另一种格式。新版hook_note、引文与公开说明同步更新。

## 承接与补写

- 从上一章已经发生的结果接续；场景前移或作者调整承接后，同时核对本章余文与下一章有效安排。旧卡中已被当前稿演出的事件不能在后续再当首次发生；未来安排需要改变时交原规划入口，不宣称已经同步。
- 补足篇幅前核对已有场景的动作、对白、人物判断与已交代信息，只增加当前缺少的行动、证据、选择或后果。不能将落座、试伤、辨认面孔或同一句对白换个说法再写一遍；补写后在同次交稿顺读相邻段，不额外请求一轮自查。

## 展示

正文不夹修改说明；公开说明简述具体变化及尚待核对之处，不罗列“已经调用某技能”冒充效果。长度分支保持章节功能；局部补写不扩章，压缩不删独立事实和伏笔。程序复核仍可拒绝错版或越界替换。

## 落稿和闭环

选区修订会实际替换当前草稿，不能标成只给候选；只想看方案时不进入落稿工具。修前锁原文、修后核邻接与后文指代，旧版通过不能签新版。只改稿、改后审核和改后接受按原目标分别结束，条件不满足保留断点；已有成功写入先核版本再恢复，不重放。真实变化、越界拒绝、审核和调用回执进入本书经验，技能内容改进先交未启用副本。

作者可在设置逐步查看[完整流程说明](references/process.md)的分支、验收和异常去向。
