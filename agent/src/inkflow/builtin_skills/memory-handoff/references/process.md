# 记忆交接：从正文变化到可提交的记忆候选

## 谁在什么情况下做

只由当前协作模式的memory_owner执行。日常可能是Editor，记忆专项启用时可能是Memory Keeper；不能同时再加一份同职责请求。当前正文、未来计划、Writer说明与已接受历史分别有身份，草稿记忆只能是候选。

## 1. 核本次来源与已有记录

输入：当前正文和版本、已接受前史、现有事实与事件、设定合集、承诺合同及Writer附件。
操作：确认这是主交接、记忆修补还是短引文选择；旧候选是否仍绑定同版来源。
输出：可用来源范围、可复用候选和具体缺口。
验收：错版、来源缺失或当前角色没有记忆职责时停止；不从摘要猜稳定ID或原文。
展示：说明正在整理候选，不能声称正史已更新。

## 2. 分清发生、相信、转述与打算

输入：与增量有关的连续原句和人物认知来源。
操作：客观行动、人物信念、传闻与未来安排分别记录；保留说话人、否定、时间、条件与不确定性。
输出：当前Schema支持的事实身份和原文依据。没有独立变化就不再建同义记录。
验收：人物说“我拿到了”不能直接当成物件客观已转移；规划中安排的事不能倒灌过去。

## 3. 提出事实与时间线增量

输入：现有稳定记录和本章实际新变化。
操作：区分新增、更新、结束与重复；更新沿真实ID、来源和有效区间。事件必须是正文实际行动或状态变化。
输出：事实、变更、事件和关系候选。explicit/inferred时间须有非空时间标签及原文依据；unknown保留未知，不猜日历。
验收：引用支持完整命题，关系指向实际提供的事件ID；不同日期相似动作不能按相似度覆盖。

## 4. 核设定更新与承诺推进

输入：真实记录ID与revision、已定义的承诺合同、正文行动和完成条件。
操作：已有对象沿原记录更新，有据首次出现才建档；承诺的plant、advance、payoff或delay须有对应动作。paid必须逐项满足触发与完成条件。
输出：setting_updates、threads等候选，未满足的条件及缺来源项明示。
验收：到了预计章段、人物猜测或部分答案都不等于兑现；正文通过不等于所有Writer附件可接受。

## 5. 按当前步骤交正确根结构

主交接：交ModeCheckOutput，verdict、confidence、summary在顶层，memory_patch在内层；纯记忆分派不填正文assessments。
修补：按当前MemoryPatch结构只补指定缺项，不扩写为另一份全章报告。
引文选择：交EvidenceSelectionBatch，逐条给fact、candidate或drop及依据，不输出完整记忆补丁。
派生重建：仅在原流程明确要求且有同版完整来源时读派生修补标准，不能借重建改变正文。
验收：原Schema、来源、时间与引文检查通过才形成相应有效候选；只装入技能或模型返回不算完成。

## 6. 正式提交、中断与闭环

输入：当前正文接受状态、审核结果、有效记忆候选、原版本与提交权限。
操作：正式写入由引擎独占，核正文版本、角色、来源和必要检查；候选整理者不能直接提交。提交后依实际状态衔接后续章节。
失败交接：取消或状态未知先查是否已经写入，再续未完成项；已完成的正式提交不重放。候选冲突交责任角色或作者决定，不能删历史解决。
展示：分清“候选已整理”“缺依据待核”“已正式保存”，列少量关键变化和下一步。
经验按真实任务与技能版本记录；创作效果留本书，通用故障与成本仅共享短投影。自动学习不能把未接受候选升级为事实，也不能直接改写技能。
