# 记忆增量标准

只供当前memory_owner使用。输入为同版正文、已接受前史、真实候选及当前Schema；不根据技能文件自行扩充数据或改变正式提交权。

## 一、认识身份

| 类别 | 判断依据 | 输出要求 | 不允许 |
| --- | --- | --- | --- |
| 客观发生 | 正文直接呈现的行动、状态和结果 | 对应原句与当前来源 | 用规划或Writer说明替代证据 |
| 人物信念 | 谁认为、怀疑、误解或知道 | 保留主体、内容和认知来源 | 变成全知事实或替其他人物知情 |
| 传闻/转述 | 明确的说话人与流传关系 | 保留归因、范围、不确定性 | 删除“据说”后当事实 |
| 未来规划 | 尚未发生的安排或假设 | 保持hypothesis等合法身份、附规划出处 | 倒灌已接受历史 |
| 未知 | 没有足够证据确定 | 明确unknown、null或待核字段 | 为完整率补造日期、ID、动机 |

## 二、事实与状态增量

先对比已有有效事实，区分新增、更新、结束和重复。更新保留原稳定ID、来源及有效区间；相似句可能发生在另一天或属于另一视角，不能按相似度覆盖。原文未说明的状态不猜；旧索引失效也不证明历史事实为假。

facts和fact_changes按当前Schema填写，动作对应实际变化。引用支持完整命题，包括主体、否定、时间、条件和程度。没有独立变化不再建一条同义记录，不以条目多证明质量。

## 三、事件和时间

事件必须对应正文实际行动或状态转变。time_status=explicit/inferred时，event_time填非空时间标签，time_evidence给原文依据；time_status=unknown时，event_time用null，不用时间证据句冒充时间标签。inferred只做有原句支撑的合理时间关系，不凭当前章号编日历。

事件关系只引用本次实际提供并核实的事件ID；目标不明保留未知，不能编前章编号。不同时间的相似动作可分别存在，人物观点和未来设想不作为客观重复事件合并。

## 四、设定合集维护

当前正文人物、场景、道具确有新增或变化时可交setting_updates。已有对象用record_id与expected_revision；首次有据出现才建档。没有变化或未说明字段留空，不重建同一对象、不覆盖已核内容。

普通讨论不自动升级硬规则。允许从现行规划原句整理未发生设定，但必须是hypothesis且有规划出处。关闭持续记录的合集不自动写入。Writer提案须由当前记忆责任角色独立核对，不能因为正文通过全部照收。

## 五、承诺生命周期

沿真实thread_id、PromisePlan与plan_source_id/hash，说明本章实际plant/advance/payoff/delay及连续evidence。逐项condition_checks写条件、met/unmet/unknown、来源章和quote；前章met还要保留真实source_version/source_hash。

paid需要全部trigger_conditions与completion_criteria均met且有对应原文，本章也有实际回应结果。到了预计章段、人物猜测、重复线索或局部答案不足以paid。未触发保留open/advanced，延后说明理由，不自动改条件。旧条目无合同如实待核。

## 六、交付前核对

纯memory分派assessments为空。ModeCheckOutput是完整报告根结构，memory_patch是内层，不把source_comparisons等审核字段塞进去。候选引用与版本一致，未解决冲突明示；程序核正文接受、版本和引句后才正式提交。

公开说明讲本章实际新增或改变的关键记忆，少量重要缺口明确列出；不复制整章，不把“候选已整理”写成“正史已保存”。
