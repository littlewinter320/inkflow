# 有据审核

审核要说明“哪句话、和哪份当前来源、发生了什么具体冲突”。Editor或Reviewer只承担本次分派；分数、命中次数和模型自评不能代替证据。

## 可执行流程

本技能为混合类型，scripts/workflow.json安排原章节审核工具；该工具内部按当前模式分配正文审核与记忆交接，不由技能额外增加角色。只审查不改稿，接受仅在原目标已授权且当前条件满足时执行。同版通过复用，资料不足保留原断点，不新增选择模型调用。

## 触发范围

被动触发于实际审核或已定位的证据纠错节点；主动点名也只能审作者授权的范围。仅逻辑检查不加载完整写法示例；仅表达不重复逻辑专项。记忆交接由记忆责任分支处理，不因正文通过自动批准附件。

## 分步输入与输出

| 部分 | 输入 | 核对方法 | 交付 |
| --- | --- | --- | --- |
| 确认职责 | 当前角色、唯一检查项、正文版本 | 区分主审、表达、连续性、同章或争议短核验 | 本次应填的维度与允许范围 |
| 通读 | 本版原文、作者要求、有效规划和前史 | 先找人物实际目标与局面变化，不按关键词猜剧情 | 有不同原句支撑的focus_observation |
| 对照 | 当前断言与真实来源 | 核对同主体、对象、事件时间和事实层级，再做共存检验 | source_comparisons及真实evidence_relation |
| 定问题 | 有定位的冲突、缺失或病句 | 读[证据标准](references/evidence-standard.md)，区分硬矛盾、普通歧义、资料不足与偏好 | 有原句、有影响、有最小修法的findings |
| 补缺 | 缺少的必要原文 | 使用现有source_queries和补源节点；没有命中不能证明不存在 | 精确缺口；不让Writer为无依据指控改稿 |
| 交付 | 本次核对结果 | 只填本次Schema要求的检查；普通建议不冒充阻断 | 当前审核结构和清楚的作者说明 |

## 输出标准

主审的六维及证据关系按reference与当前Schema填写；表达角色仅评readability，纯记忆角色不填正文量表。双方引文必须是对应版本连续原句，不拼接、改写或借Writer解释补证。公开总结先说有没有影响理解或关键因果的问题，再说明具体位置；只审查时不给建议自动落稿。

## 核验、停止与反馈

完整报告的verdict、confidence、非空summary在顶层，不能用memory_patch内层说明替代。字段错误由原角色定向补正；来源不足先检索补读；判断争议回原审核或作者。只有原程序核过当前版结构与依据才形成有效结果；pass不代替接受，unknown保留缺口。真实补正、补源、未完成和用量都进入经验，不用高缓存冒充审核正确。技能改进先给候选，不在后台换版。

作者可在设置查看[完整流程说明](references/process.md)；模型仍按完整审稿或定向短核验分别加载现有标准。
