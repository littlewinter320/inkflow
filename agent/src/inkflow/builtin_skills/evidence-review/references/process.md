# 有据审核：从当前原文到可解释的审核结果

## 入口和角色

输入必须是当前正文、真实来源、作者要求与本次检查项。Editor或Reviewer只做分派给自己的部分；纯记忆整理不用本技能。主动点名不扩大检查章段。原章节审核工具内部安排当前协作模式的表达、逻辑和记忆职责，不因为技能同时命中就各审一遍。

## 1. 锁定同版原文与职责

输入：章号、正文版本、来源身份、本次instruction及当前check_owners。
操作：区分综合主审、只表达、只连续性或定向证据核验。查同版有效完成记录，确认这次有没有真正的新版本或新问题。
输出：本次应填的维度、需要对照的资料以及可以复用的结果。
验收：错版、错角色、未经分派或只读目标外的内容不能继续。
展示：说明当前谁在做什么；已经装入技能不代表审查已通过。

## 2. 顺读与有据对照

输入：本章完整必要原文、有效规划、作者要求、必要前史与设定记录。
操作：先理解人物目标与局面变化，再核同一主体、对象、时间和事实层。引用必须来自实际提供的对应版本连续原句，不能拼接或改写。
输出：具体观察、来源比较和证据关系。普通留白、不同日期或人物信念能够共存时，不判排他矛盾。
验收：引文存在且支持完整判断；相同关键词不证明结论成立。
失败交接：查不到材料标记缺证，不把“未检索到”写成“从未发生”。

## 3. 分清错误、歧义和写法建议

输入：可定位的问题及双方依据。
操作：硬矛盾、关键因果缺失、明确要求未覆盖，按当前规则给有据问题；轻微病句、重复和不自然对白说明阅读影响；纯偏好不升格为阻断。
输出：当前Schema规定的assessments、findings和必要修法。综合检查和表达专项的填项范围不同，不能复制整套量表。
验收：必需项failed必须有相应实证；分数、自信和模型说“通过”不能覆盖程序发现的证据缺口。

## 4. 字段补正和来源补读分开处理

字段缺失：保留已返回报告，只由原责任角色按错误路径补正；例如顶层summary缺失不能通过重写整章解决。
来源不足：沿已有检索与补读节点提供必要原文，再由原责任角色核对。补源仍可能需要模型请求，必须记录真实用量。
判断争议：先回原审核或作者选择，不让Writer替无依据的指控改稿。
输出：修正后的同版报告或具体待核项。范围、版本和原预算继续约束，不能通过换任务名称重置次数。
验收：原结构与引文核验实际通过，才能结束相应检查；仍缺证就保留unknown。
展示：明确说“字段已补齐”“依据仍待核”或“本版通过”，不能统称完成。

## 5. 交付与后续分流

只审查：交报告和建议，正文保持原样。
有据修订：仅在原任务有修订授权时交Writer，修后必须对照新版，不沿用旧版通过。
允许接受：还需记忆候选及正式提交条件满足，由引擎执行；正文通过不自动批准全部附件。
输出：结论、关键原句、具体影响和下一步。报告的顶层verdict、confidence、summary与memory_patch内层字段分开，根结构以当步Schema为准。

## 6. 恢复和自动学习

取消、超时、断流时先查真实返回和保存状态。已有有效检查不重做，未知用量不记零。新版、来源或配置改变时重新核绑定，不能用旧报告签新版。
经验记录绑定任务、技能版本、实际角色、尝试和产物；未通过、补正和补源都保留。自动学习只帮助选择，不把高缓存当审核正确，也不因单次失败自动改写技能。
