# 外部Skill兼容与适配

## 接受的入口

支持包含SKILL.md的普通目录、单个SKILL.md、单技能ZIP。ZIP可有一层或多层共同包目录，但必须含唯一入口且不能混入目录外文件。多技能仓库分包导入，不猜哪个技能代表整仓库。

标准YAML的name、description必需；license、compatibility、metadata、allowed-tools等保留。要求UTF-8，包内相对路径，不跟随链接或目录联接。单包最多80文件、2MB，单文件500KB；过大先精简，不静默截断原文。

## 不同宿主的能力

| 外部内容 | 墨流如何处理 |
| --- | --- |
| 标准SKILL.md | 可读取；未带适配清单默认手动调用 |
| 入口明确链接的references文字 | 同次激活按包内路径装入；未随包提供时提示补齐，不联网补猜 |
| agents/openai.yaml或其他宿主配置 | 原文件保留供查看，不当成本宿主权限 |
| allowed-tools里的Read/Write/Edit/Bash等 | 保留说明并提示适配；不映射成任意磁盘或shell访问 |
| scripts中的Python/Shell/JS | 原样保存供外部修改，不执行、不自动安装依赖 |
| scripts中的墨流登记工具JSON | 格式与工具名核对后，在实际当步运行宿主代码 |
| MCP服务器、依赖安装、网络请求 | 不随导入注册或安装，需已有功能与另行授权 |
| 图片等二进制assets | 保存并显示资源清单，不自动当指令或加入模型 |
| ${变量} | 可通过墨流parameters声明并由作者填空 |
| 外部模型或输出Schema | 不替换正式生产Schema、角色或当前供应商 |

兼容指令不等于完全复现另一宿主的工具。需要某外部能力但墨流未登记时，明确写“不支持的步骤”并调整为现有流程；不能假装执行过。

## 导入顺序

1. 预览真实来源，列出全部文件、说明、内容哈希、触发规则及兼容提醒；不写入、不调用模型。
2. 作者选择个人或本书范围，保存预览的同版内容；变化了重新预览，重名拒绝覆盖。
3. 默认未启用。外部编辑先改SKILL.md及适配清单，不修改应用门禁。
4. 启用绑定当前内容哈希。要被动触发，还必须有具体节点、角色、when和not_when；只手动的标准包不能直接开被动。
5. 新任务冻结启用库，当前任务按原冻结材料运行。导入或外部修改不能改变旧任务的输入身份、预算和回执。

## 主动调用与歧义

@builtin/名字、@personal/名字、@book/名字精确选库；@名字按本书、个人、内置优先选择一个已启用版本，不叠加同名方法。未启用、损坏或不兼容时给具体原因，不静默忽略。只说技能名未给目标不能创建新的小说任务。语音“使用中文自然表达技能……”沿同一后端解析，引用与代码里的@不触发。主动调用仅作用当前任务及其恢复。

## 外部编辑与独立开关

作者在设置选择“写法与参考文字自动用于新任务；控制变化先确认”（默认），或“全部修改先确认”。角色、contracts、when/not_when、参数、工具脚本和流程变化均属于控制变化；对照上次批准与当前控制配置，重新启用才生效。正在运行的任务始终沿原快照。

个人库共享文件，每本书开关独立。设置可改本书覆盖、改个人默认或恢复继承；一本书关闭不会改其他作品。同名副本优先级与独立开关同时适用。

## 来源与许可

逐项保留原作者、URL、许可证、核对时间及文件内容版本。prompts.chat的源代码/网站内容与用户提示词数据许可不同，不能一律当CC0。Humanizer-zh、Ponytail的工程与表达方法应按小说权限和作者目标适配，不照搬任意写文件、安装、整会话常驻或测试规则。Headroom是上下文工具项目，墨流同名技能仅借鉴方法，不声称已部署其代理或压缩模型。
