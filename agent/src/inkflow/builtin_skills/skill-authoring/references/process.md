# 技能创建与适配：从需求到启用后的版本迭代

## 入口与权限

作者明确要求创建、完善或适配技能，才由Coordinator生成内容候选。查看目录、预览、开关与打开文件夹是本地操作，无需模型。模型产出文件候选，SkillLibrary校验与保存，作者决定启用。技能不能修改应用源码或增加任意程序权限。

## 1. 判断应该用Prompt、Skill还是Tool

输入：作者目标、任务频率、协作复杂度与现有工具能力。
操作：几句话能说明的一次性要求留Prompt；可复用方法或条件流程进Skill；路径校验、版本、提交等确定性检查留Tool与引擎。
输出：一个明确职责和承载方式。复用既有技能优于新建重复包。
验收：不能为了“有技能”把普通要求拆成多轮模型调用，不把代码门禁挪进说明。

## 2. 定名字、触发与退出

输入：真实角色、现有节点、本书或个人范围以及相近技能。
操作：name与目录一致，中文显示名便于查找；description简短写能力与具体触发。正文补充主动调用、被动节点、排除条件、缺资料和退出条件。
输出：可辨识的名称、角色与contracts；自动触发须有具体可执行边界。
验收：当步匹配仍由程序检查。when/not_when是语义说明，不能替代角色、节点、启用与权限门禁；小说引文中的@不会成为新调用。

## 3. 拆出能完成和能恢复的步骤

输入：原目标、必要资料、预期产物与失败风险。
操作：每步写清输入身份、具体处理、输出交给谁、满足条件和失败去向；区分必做与按条件。创作方法给判断标准，固定步骤只用于可靠性或权限确有需要的部分。
输出：短入口及详细参考。复杂技能可有references/process.md供设置阅读；正常模型执行只加载适配清单中匹配当前步骤的参考。
验收：从进入到结束、失败、取消和恢复都有明确出口；不能只写“认真检查、继续优化”。
展示：用作者能理解的动作名，保留正式Schema但不把内部字段当普通使用说明。

## 4. 配资源与适配外部能力

输入：步骤真正需要的标准、模板、登记工具和原包许可。
操作：references保存按需规则；scripts只声明已登记工具；assets保存确会用于产物的模板或素材。简单技能无需凑三个目录。
输出：必要资源、来源、兼容提醒和不支持的步骤。脚本中的外部Python或Shell可以保存查看，不能自动执行。
验收：链接与资源真实存在，角色和工具可用；外部宿主的allowed-tools、MCP或依赖安装不自动授予本软件权限。

## 5. 校验、预览、保存和启用

输入：SkillDraft的真实文件集合、目标范围和来源版本。
操作：skills.validate绑定的SkillLibrary.create实际核路径、大小、格式、工具与流程。外部导入先预览，同版保存，重名拒绝覆盖。
输出：未启用候选、文件目录、触发说明和实际校验问题。模型说“已保存”不算回执。
验收：作者能在设置查看全部内容，必要时外部修改后重新查看；作者启用当前版本后才可主动或被动采用。
失败交接：校验失败保留具体原因，不能丢掉不支持的步骤后宣称完整适配。

## 6. 真实使用、反馈和版本更新

输入：实际任务、技能精确内容版本、工具与模型回执、作者反馈和有效产物。
操作：原经验库记录结果；自动学习仅辅助选择。作者明确差评或多个独立任务的共同失败可产生调查建议，先分清技能、程序、资料、配置和供应商原因。
输出：有来源的建议；作者明确要求改进后生成未启用副本、变化与来源，不自动改原包。
启用后：新任务冻结新版本；进行中及恢复仍沿原版本。改版后的选择经验重新积累，不能继承旧版分数冒充验证。
文本自动更新与全部确认按作者设置；角色、触发、工具与流程变化需要重新启用。
跨书：文风与效果留本书；通用故障和调用观察只共享有限投影。
停止条件：无新证据、不支持的能力、作者取消或未获改写授权时停下；不后台付费自我优化。
