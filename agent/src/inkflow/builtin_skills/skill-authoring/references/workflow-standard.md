# 流程技能与方法技能的结合标准

## 类型与责任

method说明如何判断、写作或交接；workflow声明已有工具怎样衔接；hybrid同时包含两者。roles限定方法内容给哪些现有角色读取，Coordinator作为协调者读取流程声明。执行角色由登记工具确定，不能在文件里把Coordinator改成Writer或让审核代签接受。

## 声明位置

agents/inkflow.json的kind为workflow或hybrid，并以workflow.path引用scripts/workflow.json。这个JSON由共享编译器解释，只能产生原DispatchStep或调用已登记整体入口；不是Shell、Python或任意表达式。

章节声明的schema_version为1，executor为chapter_tools；actions限制适用目标；steps最多20项且依赖无环。步骤字段：

| 字段 | 含义与检查 |
| --- | --- |
| id | 包内唯一，小写字母、数字、连字符 |
| tool | 原登记章节工具名，必须还在本次用户目标授权内 |
| depends_on | 前置步骤ID；不能引用不存在的节点或形成循环 |
| required | true为必做；若未获本次授权就停下说明，不自动扩大目标 |
| default | 可选步骤的默认选择；未默认时由Coordinator已有tool_steps选择 |
| when | always、draft_missing、revision_needed、review_needed、ready_to_accept之一 |
| actions | 可选，进一步限制适用目标；其他目标跳过并留原因 |
| review_order | any、before、after；按原任务“先审后改/先改后审”选择分支 |
| round | 0至2；非零不得超出原任务修订轮次，后续修订只由当前版patch触发 |
| instruction | 不超过1000字的当步要求；不授予新工具、范围或角色 |

必做是“该环节的效果必须满足”，不是重发已完成的请求。已存在同版通过、没有需要修订的问题、接受前提未齐时，用真实条件与回执处理，不能拿跳过当假执行。

## 编排及复用

1. 当前原话先确定目标、章号、允许动作和禁止项；技能只能在这个集合里编排。
2. 同名按本书、个人、内置选择一版；明确@库/技能名优先。不同流程先看明确匹配、原Coordinator同次选择及本书同版经验；仍有实质分歧才询问，不为选技能额外发请求。一次只选一个流程，方法可以组合。
3. 由程序填执行角色、章号和输出要求，逐项核权限、依赖、来源与预算。
4. 同一任务冻结实际技能和图版本。恢复核原步骤来源及完成回执，文件变化不能偷偷换流程。
5. 未决资料、争议、未知返回或取消停在原节点；技能流程不为“重新选下一步”单独加模型请求，也不重置原次数。
6. 所有步骤返回后还核实际目标产物，不能只凭模型自述或节点数量宣布完成。

## 整体事务入口

executor为registered_workflow时，只指定已登记actions与说明，不接受自定义内部steps。规划发布、批次晋升、逐章接受等已有事务需要保持恢复和提交保证，技能通过原入口衔接；不能把它们拆成绕过版本核验的新路径。

章节工具图目前只在明确单章范围展开。批次及continue_run沿原整体引擎入口执行，方法技能仍按各角色实际阶段装入。这里的边界须在技能说明及外部适配时写明，不能宣称任何流程都可任意编排。

## 状态与成本

默认常显当前关键阶段；展开看选中了哪版、哪些参考已读、本地工具做了什么、哪些分支为何跳过、哪个角色正在等模型。思考参数不等于服务端正在思考；只有实际思考/正文字段信号才能说明相应进展。

预处理工具、编排、条件判断、目录和状态展示本地执行。技能选择额外模型调用为0；真实生成和审核沿原调用、预算与用量账本。实际缓存仍看供应商实报，不用技能自评证明省钱。
