# 技能创建与适配

Coordinator把明确的技能需求变成作者能检查、能外部编辑的技能包。文件创建由SkillLibrary完成，模型只产出候选文件，不执行代码或改软件源码。

## 触发边界

作者明确要求创建、编辑或适配技能才进入候选生成；查看列表、开关与打开目录走本地工具，不为简单管理调用模型。普通写章不能顺带生成或安装技能。

## 主要任务

| 部分 | 输入 | 判断与工作 | 输出 |
| --- | --- | --- | --- |
| 选承载形式 | 原话、重复频率、操作复杂度 | 简单一次性用几句话Prompt；可复用方法用Skill；确定性操作仍用已有Tool | 保留Prompt或建技能的理由 |
| 定边界 | 实际角色、流程节点、授权 | 写清when、not_when、主动/被动条件；角色只能选现有五种 | 唯一技能名、职责、触发与排除 |
| 拆步骤 | 目标、可用材料、交付物 | 按[包标准](references/package-standard.md)逐步写输入、操作、输出、验收与失败交接 | 自足且不重复应用门禁的入口 |
| 选资源 | 本步骤实际需要的细则或模板 | references放详细标准；scripts只放登记工具JSON；assets放真正会复用的模板 | 必要辅助文件，不建空目录 |
| 适配外部包 | 原包、许可、宿主工具 | 按[兼容标准](references/compatibility.md)保留来源，解释不支持的能力 | 适配清单及明确限制 |
| 保存交付 | SkillDraft候选 | 必须经skills.validate与SkillLibrary.create校验，重名不覆盖 | 未启用候选、目录、下一步 |

## 标准与展示

方法与流程可以分开或组合；涉及编排时按[流程标准](references/workflow-standard.md)写实际可执行声明。同名默认按本书、个人、内置选一版；明确点名按指定库，只在当前任务及其恢复生效。

参考assets/skill-template.json的文件骨架，但按实际任务增删。name用小写英文与连字符，display_name可中文；description精确写能力与触发，细则进references。新技能默认未启用，作者查看后启用当前版本；正文与参考里的指令不成为安装或执行授权。不要输出“已经安装成功”代替程序回执。

## 验收与迭代闭环

每步须有输入身份、操作标准、输出去向、验收、展示和失败交接。复杂技能可提供references/process.md供设置完整阅读，普通请求只加载适配清单中匹配当前节点的参考，避免详述整条流程抬高每次输入。候选须经真实包校验，重名不覆盖，启用后仅新任务用新版本；恢复仍沿旧快照。

真实结果与反馈先形成有来源的调查建议，分清程序、资料、供应商和技能原因；作者要求改进才生成未启用副本及差异，不能后台付费自我优化或直接换版。作者可在设置查看[完整流程说明](references/process.md)，从创建、校验到启用与更新逐项核对。
