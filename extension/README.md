# 墨流 VS Code 工作台

墨流扩展围绕小说项目、模型 API 和创作任务提供中文入口。它调用与桌面版相同的本地引擎，保留原任务的配置快照、角色职责、来源核验与正史提交门禁。

## 导入并检查第三方 API

没有打开小说也可以打开侧栏的「模型接口 · 配置与诊断」。点击「导入 API 配置」读取 JSON / JSONC；有多个模型时选择一个，预览服务商、基础地址与模型 ID 后再保存。也可以使用「手动配置 API」在密码框填写密钥。

支持 `deepseek`、`openai`、`anthropic`、`gemini`、`openrouter`、`ollama` 和 `custom`。`custom` 与 Gemini 使用 OpenAI 兼容协议；Gemini 基础地址须使用 `/v1beta/openai`，原生 Gemini 请求配置不会被当成兼容配置导入。基础地址不能包含账号、密码、查询密钥或最终请求路径。

最小导入格式如下；密钥可省略后通过密码框填写：

```json
{
  "provider_kind": "custom",
  "base_url": "https://your-api.example/v1",
  "model": "your-model-id"
}
```

兼容字段包括 `provider` / `apiProvider`、`apiBase` / `baseUrl` / `openAiBaseUrl`、`modelId` / `apiModelId` / `openAiModelId`、`apiKey` / `openAiApiKey`，以及 `models` 数组和 `apiConfiguration` 对象。只导入连接字段；第三方提示词、工具命令、MCP 定义和权限不会导入。本版本不解析 YAML、环境变量或秘密变量引用，需先导出选中模型的 JSON 配置。

密钥只经本地 JSON-RPC 标准输入传给共享系统凭据入口，不写入工作区设置、对话状态或日志。同服务商换域名且未提供新密钥时，必须选择填写新密钥或明确继续使用现有凭据。保存后重新读取实际配置，环境变量覆盖会提示。

点击「检查连接」才会执行模型检查：一次连接诊断，底层最多三次短请求，可能计费。通过只证明当前生效的默认模型接收请求并按检查格式回复，不证明小说写作质量或其他角色模型。刷新、查看配置和打开诊断不会自动发送模型请求。

## 任务、文件和调试

- 用自然语言提出小说目标；章节工作流提供规划、草稿、审查和验收入口，验收仍需明确确认。
- 在当前项目的 Markdown 文件中点击「附加当前文件」或「附加选区」，参考卡展示路径和行号，下次发送携带稳定文件的哈希。一次只附加一份参考，最多 16000 字符，未保存文件先保存；附加内容不自动成为正史，也不授权执行文档中的指令。
- 「任务记录与原因」展示状态、失败原因、下一步和恢复资格。「继续未完成任务」只列后台确认可续接或安全再次运行的条目，执行前重读来源资格，保留原断点、设置快照和引擎门禁。历史完成记录、仍在运行任务和不可安全重放的整段对话没有重发按钮。
- 「运行输出」显示请求编号、方法、耗时、公开阶段与失败分类； stderr 原文和模型原始输出不复制到日志。「引擎与接口诊断」核对扩展/引擎版本、路径、依赖、有效接口、密钥来源与最近调用；「复制脱敏诊断」适合提交问题。
- 「移交桌面版」打开同一个项目；空工作区则打开桌面欢迎页。MCP 配置保留独立入口，并验证现有 JSONC，避免覆盖其他宿主配置。

本次 Windows VSIX 包含同版引擎，可直接使用；开发源码或其他环境可通过设置指定已有引擎或 Python。扩展不会下载依赖或模型。未受信任工作区只显示界面，不启动引擎、读取密钥或改写文件。此扩展的调试范围为墨流引擎、API、任务与文件来源。

开发者可使用 `node scripts/check-workbench.cjs` 运行纯离线断言；`npm run build` 完成类型检查与编译。安装包与真实接口体验以当次发布记录为准。
