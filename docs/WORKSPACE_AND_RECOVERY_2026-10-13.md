# 0.7.5 源码增量：直接布局、定点修订与可用资料回退

本轮先完成用户已提出的界面、工作流及记忆处理调整，再继续小说。源码版本仍为0.7.5；本记录不改变10月11日的标签、安装包或发布验证。具体源码在 PR #4 的同一修复分支，当前发布包身份见[发布记录](RELEASE_0.7.5.md)。

## 设计取舍与实现范围

| 用户遇到的问题 | 本轮采用的设计 | 已改入口与边界 |
|---|---|---|
| 设置页靠位置选项、滑块反复调布局 | 面板自身可直接操作，关闭后从顶部紧凑布局菜单重开 | `Workspace.tsx`、`workspaceLayout.ts`、`workspace.css`、`App.tsx`；小说结构、墨宝对话、批注与版本三个面板，移除旧布局设置与重复定位入口 |
| 大屏也受固定宽度限制，缩窗后容易挤掉正文 | 上限取实际工作区尺寸；停靠保留正文阅读空间，不足时临时浮动 | 左右停靠、下方停靠、浮动；侧栏边缘、下方高度和相邻宽度、浮动八方向可调；小窗口适配不改写用户保存的原尺寸 |
| 独立、转换、关闭后缺少回归路径 | 拆出真实系统窗口，共享原任务；“返回工作台”、关闭和布局菜单均可回归 | Electron、preload、窗口类型与界面调用一起更新；独立面板不是新的聊天任务，不创建第二份生成请求；新增独立对话沿原有 conversation_id 隔离 |
| 拖动带着整个小说界面反复渲染 | 拖动帧只更新面板与编辑区矩形，松手提交布局 | requestAnimationFrame、5像素启动阈值、指针取消/失焦/Esc收尾、键盘微调；停靠落位用180毫秒过渡，减少动态效果设置下关闭过渡；未实测帧率 |
| 自动修订仍收到整稿交付和补字要求 | 局部接口只请求原句补丁，模型说明与实际修改分别核对 | `prompts.py`、`engine.py`；最多四处，原句唯一、非重叠、标题和范围外字符保留。整稿交付路径继续使用自己的输出结构 |
| 修了两次却无改善，下一次仍重复同样方法 | 根据当前问题类型与上次真实结果选择局部方法 | 原文未变记 no_change，未通过记 unresolved；记录前后来源、报告和问题证据。只有当前来源的完整通过报告才记 verified，不用 Writer 自称完成关闭事项 |
| 报告摘要、实际问题和修改要求不一致 | Writer 同时读取结构化结论、逐项证据及 repair_instruction | 摘要不是放行依据；资料缺口与未获支持的指控先核源；不让 Writer 为审查取材问题改正文 |
| 可选语义服务失败就拖住可用检索 | 保留精确匹配与BM25，重排失败保留原排名融合 | `retrieval.py`；本地模型只读已缓存资源，失败原因在诊断留档，无自动下载和新依赖 |
| 摘要失效后空掉原有资料名额 | 核原文版本和段落，失败候选从已排名资料中有限补位 | 仍遵守最终top-k、章节边界、来源身份和上下文预算；事实可关联同版源章，不把摘要或规划直接当正史 |

面板关闭只改变可见性；“回到上一步布局”撤销最近一次布局修改，恢复初始布局也能返回独立面板。独立窗口的临时移出状态不写成永久隐藏，避免重启后找不到面板。正文编辑区仍是阅读与写作主区域，没有引入任意拆分编辑器、额外停靠库或新的窗口任务引擎。

新增覆盖拖靠：左右区域随工作区宽度、下方区域随高度形成覆盖候选，面板可见面积覆盖达到45%才进入，已经命中的方向降至30%才退出，减少边界抖动。预览使用提交同一份布局计算出的实际矩形，小窗口无法容纳停靠时保留浮动。拖动标题到临时收起区可隐藏面板，拖出工作区阈值可拆到鼠标所放位置的系统窗口；不删除小说内容，原对话与任务仍共享。拖动独立窗口进入主工作台使用同一覆盖预览，Windows原生`will-move`/`move`显示预览，`moved`结束才提交，暂停不当作松手。取消、缩放、系统贴靠和失焦清理预览；未命中继续独立摆放。拆窗位置按目标显示器工作区及缩放适配，返回时沿用窗口尺寸。顶部菜单保留恢复与单步撤销入口，按钮不再是转换的必要条件。

参考 [Dockview浮动组文档](https://github.com/dockview/dockview/blob/master/packages/docs/docs/core/groups/floatingGroups.mdx) 的标题拖动与视口边界，以及 [Electron窗口事件实现](https://github.com/electron/electron/blob/main/shell/browser/api/electron_api_base_window.cc) 与 [原生窗口移动说明](https://github.com/electron/electron/blob/main/spec/api-base-window.spec.ts) 中Windows拖动结束事件的区别。使用已有React/Electron契约实现，没有安装Dockview或复制其源码。

## 灵活工作流与反思

Coordinator 在原有一次理解调用中，根据用户要的最终产物选择现有节点，不要求查看、试写、修订、审查和接受每次全部执行。后续普通节点仍由代码推进；当前模式、授权、来源和质量门禁继续约束执行。

恢复记录使用原 task_id、配置快照、节点和两次次数。无变化、异常和中断不重置次数；当前问题仍在时，下一次限内修订依据残留原文换局部方法。补读、记忆归类和正文修订分开，保留已通过正文，从真正受影响的节点恢复。细节写入现有 trace 和学习事件，普通用户只见自然语言阶段、结果及下一步。公开过程和本地计时不增加模型调用，也不展示隐藏思维链。

采用“来源校验＋责任角色判断＋按需第二角色”，不固定设置两个额外审查 Agent。问题需要第二个现有角色时，必须属于任务已经冻结的模式与分工；正常日常任务不因此升级。方法经验可以作为后续相关任务的参考，不能携带旧小说事实、改变原设置或代替当前审核。

## 研究依据与未采用项

直接拖动、重排和保存布局参考 [VS Code 官方界面说明](https://code.visualstudio.com/docs/editing/getting-started/userinterface)；停靠、浮动、拆窗与序列化是 [Dockview](https://dockview.dev/docs/overview/introduction/)提供的常见工作区能力。本轮复用现有 React/Electron 实现，未安装该库。菜单使用浏览器原生 [Popover](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using)，由顶层显示和外部点击关闭降低遮挡。

[Reflexion](https://arxiv.org/abs/2303.11366)给出的反馈与任务经验思路适合本项目已有的恢复记录；[ACL 2025 自我纠正研究](https://aclanthology.org/2025.acl-long.1314/)提示，仅让同一个模型再次反思并不可靠。因此本轮采用实际差异、来源与当前审核结果作为反馈，不增加常驻反思模型，也不引用其基准成绩冒充小说质量提升。[LangGraph 条件路由](https://docs.langchain.com/oss/python/langgraph/workflows-agents)与[长期任务 harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)支持按状态选节点、保留进展的设计思路；本轮没有迁移引擎框架。

检索改为按排名进行 [RRF 融合](https://learn.microsoft.com/en-us/azure/search/hybrid-search-ranking)，避免直接混加量纲不同的BM25与相似度分数。[GraphRAG 官方说明](https://microsoft.github.io/graphrag/query/overview/)区分结合实体与原文的局部查询和跨全库的全局查询。本轮只增强已有事实到版本化源章的关系，不构建全书实体图或社区报告。进一步图谱工作应有真实漏召回案例与成本记录；定期归档、数据库“清洗”不会自动删除正文、审计或恢复来源。

ColorTXT 的用途与后续可选方向见[专项参考记录](COLORTXT_REFERENCE_2026-10-13.md)。网络研究按 AnySearch 协作规则进行；ColorTXT原文提取失败后使用GitHub连接器读取README及许可证，没有导入第三方代码。

## 小说与缓存的下一步

只读核验确认本次实际小说接受到第43章，第44、45章尚未发起。用户当前阶段目标为完成到45，不启动46；之后76章完结目标仍保留。第43章旧稿到已接受v2的真实改动很大，不用后来新增的局部补丁保护冒充此前已经逐字保留。

本阶段77次已报告用量的调用，输入5,985,426 token、缓存命中3,010,816 token，按输入加权未命中约49.70%，没有达到20%。同一章节审查契约的14次调用保持同一系统和前4096字符指纹，仍不能据此保证供应商缓存；五次 DraftOutput 使用过三种系统契约，修改提示词与任务类型也会影响可比性。来源检索成功率、本地向量缓存和供应商输入缓存分别记录，不互相代替。

先冻结本批源码和输入合同、上传，再用软件自己的可见对话完成44—45及必要审核，从真实账本观察新增调用。电脑控制曾收到实体Esc停止信号，目前未恢复，不能绕过停止信号改用引擎命令或宿主写小说。
