# 待办与协作台调用缺口核对

用户追加要求继续排查设计缺口、调用缺陷及重复操作。本次只核对桌面 `App.tsx` 的刷新、对话收尾、快捷建议、批次状态和协作台入口；保留已验证的设置、版本和后端实现。

## 新发现与已修

1. 快捷建议的 `assistant.suggest` 后端已经是本地规则，不能把本次优化说成减少了付费模型调用。前端原本仍在每轮对话结束（包括查看待办、暂不处理、失败）额外请求建议，并附带最近对话。现在只在完成实际工作、打开项目或启用建议时读取本地建议，去掉无用的对话负载；同项目同时请求合并，旧项目迟到结果不覆盖新项目。
2. `refresh()` 原本把可执行打开恢复的 `project.open` 与协作读取并发，同时保存完成、对话收尾可能再发同项目刷新。现在顺序打开／恢复再读取协作，同项目进行中的刷新复用同一 Promise；切换项目后旧结果不采用。只查看待办或留待下次时直接采用回复里的待办列表；状态、帮助和讨论不重新打开整个项目。
3. 闲置窗口的状态／协作刷新只检查“隐藏”，未检查失焦；批次进度对每一个运行请求都读取，且慢请求可重叠。现在失焦或隐藏时暂停这些界面轮询，重新获得焦点再读取；只有本次运行实际绑定批次或出现批次事件时读取批次进度，且避免重叠。模型执行与任务恢复并没有因此停止。
4. 高级电脑操作入口即使功能未启用，也每 2.5 秒读一次待确认请求。现在关闭且没有已显示待确认请求时不轮询；已有请求保留，以便拒绝或核对到期状态。开启后只在可操作窗口读取，重新聚焦及时恢复。原确认门禁保留。
5. 任务详情每 15 秒单独读任务列表，与全局协作概览重复。现在复用新的全局任务列表，仅打开详情和明确重读时定点读取；失败时保留已显示记录、原因及“重新读取状态”入口。
6. “让目标 Agent 回答”没有界面防重复和错误处理。现在按议题保护进行中请求、显示等待和具体失败原因，保留“查看恢复条件与任务记录”入口。后端原有来源校验及有界尝试次数仍负责能否继续。
7. 可执行待办同时有“处理”“查看依据”和已显示的展开详情，容易形成重复查看对话。现在可执行事项保留具体处理动作与已有详情；需要用户决定、条件不足的事项继续保留对应入口。实际问题、诊断、失败历史仍能查看。
8. 对话失败／等待条件时，旧写作快捷建议仍可能提示继续写章。现在直接换成本地“查看待办与恢复条件”，使用现有确定性待办命令，不自动派模型补救。批次范围核对按钮此前可能把文字放进已隐藏的对话输入框；现在点击后显示该输入框并聚焦，仍由作者发送确认范围。

## 保留的功能与待观察

- 外部手动修改的后台扫描继续执行，它是已启用的必要监控功能，不能仅因为窗口失焦就漏掉作者在外部编辑器的修改。后台工作与界面轮询区分。
- 预期减少的是本地重复 RPC、重复读取和刷新碰撞；没有重新进行付费调用或缓存性能测量，不能声称实测费用／缓存命中提升。
- 失焦再聚焦、独立对话窗口与慢本机 RPC 的实际响应仍需本次整体观察确认。既有断言脚本补充刷新范围与可见／聚焦条件；其执行和类型编译结果由主任务记录。
