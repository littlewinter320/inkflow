# 实际模型输入减量与44—50章运行记录

本轮目标是降低真实费用与未命中输入，完成到第50章，其中46—50章通过墨流可见对话一次发起批量生成。沿用现有模型、角色模式、来源门禁与接受流程。

## 发现的原因

上一阶段Writer首次正文调用输入198,790 token，后续两次为189,433和201,031 token；后两次各命中84,992 token。规划、正文、局部修改和说明短答使用不同输出合同，不能把所有Writer调用当作同一种缓存请求比较。历史阶段的77次调用加权未命中49.70%，不因本次修改而重算为新成果。

保存的第43章Context Packet中，检索分支/已选与丢弃清单、来源读取日志、待办内嵌故障记录被重复发给模型；它们随查询或任务变化，却不提供新的小说依据。检索命中原文还同时带着定位摘要和排名诊断。正文、正史证据与引用身份仍须保留，不能单纯截断长输入。

## 本轮修改

- `ContextSection.model_content()`提供模型专用投影：JSON结构去除格式空白，字符串内部的空格、换行和引文保持原样；Markdown规划保持原样。
- MEMORY保留必要来源缺口、冲突和伏笔历史，去掉重复的候选分支、排名清单和读取日志。WORK保留任务身份、状态、原因、下一步及已用次数，完整故障案卷和旧节点回执继续留在原始记录。
- F中的真实正文片段及源章、版本、哈希、位置不变；已经核回真实正文的命中不再附带定位摘要。排名分数与实体提取诊断留后台，原候选顺序不变。
- Context Packet原始内容、可读调试文件及接受用来源材料保留；缓存前缀诊断改为与实际模型投影同口径。没有修改供应商、密钥、角色权限或原补救次数。

仅对原句保留、来源身份、必要缺口和待办次数进行一份定点离线检查，通过。使用同一份已保存第43章资料比较，相关章节资料的本地token估算由159,361降至125,917，减少20.99%；这不是完整HTTP输入计费，也不是供应商缓存命中率。实际用量须以新请求的usage为准。

DeepSeek当前[官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache)要求完整匹配已持久化的前缀单元；共同前缀可能需要多个请求才能形成，缓存还会过期。因此不发送额外预热调用、不增加无关资料来提高命中率数字。分别观察首次冷请求、相同合同后续请求和46—50批次，并记录输入、命中、输出、耗时及合格产出。

## 实际运行

已重新启动当前源码开发窗口，界面确认正史至43章、当前规划正式第13版。通过自然语言对话发起44—45章写作、必要审查与按现行设置接受；后续46—50章待该范围完成后单独以批次发起。运行结果与真实缓存数据在完成后补记，尚未完成的章节不记作正史。

第44章首次交稿为3319字草稿。审核未列正文问题，但Writer说明的概括句被填入逐字引文字段；短答只说“可定位”而没有返回更正对象，造成同一说明缺口和外围恢复空转。该次Writer短答输入169,106 token、输出352 token，说明仅做通用投影减量仍不足。

针对该真实故障，说明短答只装入当前正文、说明与任务规则，未知前史交原审核角色核对。更正提示明确要求交回实际对象；代码只从同版Writer既有回答中提取在正文唯一出现的连续引文，作为更正候选送原审核角色判断。读取时保留原始说明、短答和次数，候选改变说明指纹，旧通过报告不能复用；不重新生成第44章正文。定点检查覆盖原句唯一定位、来源不改、无有效原句时不自动更正及其他问题不误匹配。

该章后续独立审查的补读输出又出现“verdict=patch但findings为空、记忆无冲突”的矛盾结构。新模型输出在Provider解析时进入一致性校验，原责任角色通过现有有限格式重试澄清结论，不自动把patch改成pass；历史结构仍可读，矛盾候选不复用为有效模型结果。Writer引文要求放在本次任务尾部，维持系统与早期资料前缀。

真实操作同时发现从搜索结果打开章节时缺少chapter_no，章节工位没有加载；入口复用已有文件名章号解析补齐，桌面类型检查通过。以上修复仍未重建安装包。

明确的单章“审查并验收”又被Coordinator口头答应但未执行。新增严格匹配完整单句的本地路由，直接进入已有review/review_accept，自动正文修订次数为0；否定、问句、复合要求及章节范围继续由Coordinator解释。定点检查覆盖这些边界。此项减少明确命令的无效理解调用，不是跳过审核或验收授权。
