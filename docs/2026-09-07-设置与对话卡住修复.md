# 设置与对话卡住：现场记录

## 已定位的原因

安装版项目页持续出现检查点查询产生的“工作流已完成”记录。ProjectCenter 的加载回调依赖 onError，而 App 每次渲染都生成新的 onError 函数。引擎事件更新 App 后触发 ProjectCenter 再次加载，形成反馈循环。

独立引擎的单次保存、保持标准输入开启的长连接保存均成功。这些检查不能替代桌面端验证。此前只修改成功提示，没有切断刷新循环，不能据此宣称已经解决卡住。

## 本次修改

- 使用稳定的错误回调，阻断循环请求。
- 保存直接使用配置请求回执更新界面，移除保存后多余的状态查询；设置保存等待超过 15 秒给出提示，联网检查另计时。
- 把过程事件列表改成任务计划，过滤检查点列表读取等后台查询，限制显示最近八项。
- 对话运行时显示当前请求的最新阶段，最终回复留在中间对话区。

计划步骤目前由任务类型提供，表示执行安排，不冒充模型针对剧情生成的完整章节规划。小说章节规划仍使用既有规划能力。

未迁移数据库，未改动小说正文。本次验证仅针对卡住与计划展示相关路径。

## 安装版验证结果

通过安装版实际渲染页面的按钮执行（不是独立 Python 引擎）：

- 点击“仅保存”：显示“设置已保存，可以开始对话。”
- 点击“保存并测试连接”：返回 deepseek-v4-flash 的真实中文问候和公开判断。
- 输入“你好，请用一句话回答你能怎样帮助我写小说。只聊天，不写文件。”：中间对话区收到模型中文答复和路由理由。
- 回答后监测三秒，后台引擎事件为零，没有再次出现循环查询刷屏。

桌面构建通过，未执行全量测试。复现脚本只用于本次安装版调试，需要应用以本机调试端口 9237 启动；运行会进行两次模型请求。
