# 待办、文件与对话界面调整记录

## DesignContext

- 任务：按用户明确调用的 Designly 流程调整墨流已有桌面界面，重点处理待办过多、动作不贴合、窄栏正文挤压和重复失败记录造成的混乱。
- 目标：让作者先看到这章需要做什么、可执行的下一步和结束条件，再按需查看角色交接、失败诊断与历史。
- 用户：在 Windows 桌面使用墨流写长篇小说的中文作者。
- 主信息：已有成果保留，从实际任务断点继续；待办与运行历史分别可定位。
- 主要操作：处理当前全部待办，或按章节选择恢复、修订复审、补核、文件同步、正式接受或用户决定。
- 平台：Electron 工作台，当前观察窗口宽约 1468 px；文件栏约 200 px、对话栏约 350 px，正文与协作台使用剩余宽度。
- 语言与视觉：中文，沿用墨流深色／浅色主题、金色重点、墨宝品牌、既有字体及设置；使用现有布局和交互，不增加依赖。
- 资料：用户提供的“已入正史 2/2”却显示项目繁忙截图，现有 App.tsx、styles.css、studio-design.css、ProjectCenter.tsx 及真实待办数据结构。
- 不可覆盖的要求：实际产物、来源与必要审核决定任务是否完成；原配置、任务身份、正文与正史门禁由引擎保留。错误历史与未解决条件仍可展开查看，界面不自行删数据或替作者批准。

## 结构与文字决策

使用 Designly Director 的约束优先级、Composition Director 的单一主要焦点和 Typography Director 的清晰文字区域。待办看板作为协作台顶部主要操作区域；文件栏仅显示待办／讨论摘要及一个入口，不再把完整角色消息与大量任务卡塞入窄栏。待办按章节分组，章号、动作、处理状态优先；具体原因与下一步可核对，关联诊断放在原任务卡下方。

行动按钮直接对应实际 `kind`／`handling`：执行卡需要修订时显示“修订并复审这章”，只需复审时显示“复审这章”，正史投影显示“同步章节文件”，原任务显示“继续原任务”，手动改稿需要用户决定时进入修改核对。条件缺失的任务仅提供查看恢复条件与留待下次，运行中的任务不提供重复处理按钮。批次接受、续接和范围核对保留各自既有门禁。

当前待办计数只计根任务和未绑定根任务的批次：完成／失效、关联诊断、已全数进入正史的批次及留待下次条目不重复计入。留待下次事项和 Agent 待回应讨论各自保留可展开区域；协作讨论数与任务数分开展示，旧失败运行仍在既有运行历史中查看。

对话顶部的批次进度仅展示绑定本次 `activeRunId` 的批次。没有本次批次时不再回退到任意旧失败／已接受批次，避免查看第 31 章规划时仍把旧 14—15 章显示为当前工作；旧批次的成果和记录继续由运行历史与原任务保存。

文字使用现有主题变量。卡片正文 12 px、标题 13 px、主要标题 18 px；动作区能换行，窄窗口不把按钮挤成逐字竖排。待办区域进入现有协作台滚动容器。对话长路径／文本可换行，文件工具栏与对话顶部控件按宽度换行，保留编辑器本身的布局机制。
