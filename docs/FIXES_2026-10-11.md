# 2026-10-11 后续修复记录

此记录描述已发布 0.7.4 之后的源码改动，不改写 v0.7.4 标签、安装包或此前验证记录。源码、媒体检查和 GitHub 上传各按实际证据记录；版本统一为0.7.5；打包与发布回执见 [本版发布记录](RELEASE_0.7.5.md)。

## 已改范围与设计依据

- 全窗口底栏只保留正文总字：读取当前版本且 hash 一致的正文，草稿与已接受章节各计一次；规划、报告、历史版本及未保存编辑不计入。全书进度分别显示已写、待核或待接受、已接受；批次的产出、审核与接受保持各自含义。
- 待处理按实际工作来源及关联关系计数，旧任务、诊断卡和角色消息不重复叠加为工作数量。原待办已被当前报告接管时，旧续接任务有据收尾；必要门禁仍独立存在。
- 拒绝是停止安排可选工作并留档；不表示审核通过或问题解决。允许拒绝额外优化、失效摘要重建和中断工作安排；必要审核、规划依赖和提交收尾保持门禁。恢复安排保留原任务身份、来源、快照及尝试次数，不立即调用模型。运行中的原任务须先停止。
- 同章规划复审负责该章诊断；诊断卡不另发整章审查。同版已经做过有界补读但仍缺依据时，先修复具体来源或输出条件，不能换卡片绕过尝试限制。
- 归因核对与当前规划对照复用已装入资料；只有明确来源查询、资料缺失或关键指控才搜索历史原文。模型输入不再附带庞大的完整检索分支诊断，完整审计仍保存在本地。必要审核和四查询、六来源、40,000 token 的补读边界不变。
- 审查生成 Schema 将 evidence_relation 明确标为必填，旧报告读取仍为 unchecked；不自动补分类或将未知结论改为通过。详见 [MiMo与生成契约](MIMO_API_2026-10-11.md)。
- 修复媒体 CSP 未允许 voice:audio-url 返回的 data:audio 地址；只增加媒体 data: 许可。音频读取、设备或解码失败使用可执行的中文提示，停止及切换项目后迟到的语音不重播。
- 小米 MiMo 的模型、地址、凭据用途、采样、输出字段及动态上限同时接入引擎、桌面和扩展；复用原配置导入、连接检查、账本和预算。保存与查看配置不发模型请求。
- 墨宝视频、动作分配、背景处理及十二帧补充以 [媒体实作记录](MOBAO_MEDIA_2026-10-11.md) 为准，用户原片保留 D 盘。只移动墨流窗口内的角色容器，成果展示不改变小说验收状态。

本地状态读取做了五组交替前后测量：使用发布源码中的实际 dashboard 方法与当前方法读取同一份40章项目，已接受字数一致；项目数据库连接数从每次82降为22，中位耗时从260.826ms降为119.151ms。当前方法还统计全部草稿字数。这只是本机 dashboard 读取的样本，不能代表整窗启动、网络模型耗时或供应商缓存命中；原始五组数据留开发机D盘。
