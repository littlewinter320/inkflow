# 进度、待办决定与音频交互改进

本次为源码改动记录，安装包、发布和真实体验以主任务的实际证据另记。未安装应用、调用付费模型或运行全量验证。

## 设计范围

沿用已应用的 Designly composition-director 与 typography-director：删掉不能直接帮助创作的常驻容量数字，不添加装饰面板。全窗口底部只显示本书当前已保存的「正文总字」，规划、报告和旧版本不计入；未保存编辑在保存后更新统计。顶部按实际章节状态显示「已写 / 待核或待接受 / 已接受」，避免审核断点遮住已产出草稿。

全书统计读取引擎的 `written_characters` 与 `chapter_progress`；缺少新统计的旧引擎显示待读取，不把正史字数冒充全部正文。批次进度条只表示本批次已保存正文，另列审核与接受，当前批次按 run_id 绑定，旧批次在来源详情中查看。`memory_status=canon` 不能独自把草稿标成已接受；阶段「开始」不显示完成勾选，计划步骤只标为计划，必要审核仍以当前来源报告为准。

## 待办决定

活动数量依据去重后的实际工作来源统计，关联诊断、批次和角色讨论单独展示。保留留到下次的事项、批次保存断点与拒绝历史。

引擎决定 `can_reject`、按钮文字和拒绝影响。界面只为明确可拒绝的事项显示按钮；必要审查、规划复核、提交收尾不能由前端猜测为可拒绝关闭。确认窗口显示原原因与影响，可附拒绝原因，调用 `project.pending_decide` 并携带当前 `updated_at`；只有后台明确返回 completed 后才采用返回的 active/history，并复读 overview。拒绝不变成问题已解决，不解除依赖，也不覆盖正文。

## 音频修复

源码依据：`voice:audio-url` 已返回经授权的 data:audio，本次主任务补上 renderer CSP 的 data: 媒体许可。App 原先 onerror 的中文提示会被 `audio.play()` 的原始英文拒绝覆盖；未绑定播放代次时，停止或切换项目后迟到的朗读结果也可能重新播放。

前端新增播放代次、当前播放器解绑与生命周期清理。停止、切换项目、较新的播放请求会阻止旧结果再播放；解码、读取、不支持格式和系统阻止分别给出可执行中文提示，已有音频保留。指定输出设备不可用时回到系统默认设备，错误可从听读页继续核对，不自动重生成或重试。音频错误不会被后续 Promise 再次覆盖。

## MiMo 设置对接

添加小米 MiMo、mimo-v2.6-flash/pro 及普通 API / Token Plan 地址选择。不同地址使用不同凭据，明确提示重新填写对应密钥；保留已运行任务快照与角色模型。MiMo 不显示可调 reasoning_effort 档位，不新增全局 thinking 设置；非思考采样输入采用已核实范围，思考请求显示服务端固定 temperature 1.0 / top_p 0.95。后端能力预览及请求约束由主任务与 MiMo 契约代理负责，未知模型上限不由界面猜测。
