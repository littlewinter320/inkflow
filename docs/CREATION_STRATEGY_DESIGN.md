# 创作策略设计访谈

状态：2026-10-15访谈已获用户确认并授权实施。本文不表示全部源码或真实小说流程已经完成。

## 已确认

- 协作方式独立于质量与消耗：日常协作3位，按需加强4位，全面协作5位。4位模式由任务选择Reviewer或Memory Keeper；避免重复职责，生产前固定选择，恢复不重选。
- 质量与消耗为节省、平衡、高质量、自定义。平衡容量采用作者本次保存的基准，自定义只解锁容量并继承上一档策略，不重置参数。
- 作者明确现有版本即平衡状态：平衡保留当前正常调度、资料准备、修复及审查方式，不另造新流程；其余档位相对该基准调整。源码缺陷修复不当作新增质量流程。
- 节省档的单次模型请求失败最多重试一次，总共两次尝试；失败、中断保留原记录，不靠换角色或换任务重新计数。
- 不设“每章额外调用配额”来鼓励用满。仅制作必要内容、修复有实质影响的问题；收益很小的润色、重复确认、多次调动不作为高质量档的固定步骤。
- 高质量写前读取与本章情节相关的正文、当前规划和适用设定，不固定前3章或前5章。装入资料与模型正确采用分别核对，不把检索未命中当作事实不存在。
- 普通续写在同次写作准备；主线转折、卷末高潮、多伏笔汇合、关键立场改变，以及作者明确标记的重点，可提出独立小规划。触发后先询问或详细讨论，不能直接新增规划调用。
- 没有事实错误时，主动重排未接受草稿的段落或场景先询问；作者倾向获准后可在本章内调整。已接受正史仍保留原保护、复核与接受流程。
- 基础表达风格、本书事实和当前明确要求不随档位被替换。更高投入不等于增加形容词、固定多写几稿或降低证据标准。
- 后台记录实际调用、输入、缓存命中、输出、耗时及合格产物成本；缓存命中与检索覆盖、设定采用、文学质量分别衡量，不用预热或重复失败抬高数字。

## 后续确认的取舍

- 四人同时遇到连续性与记忆需求时保持四人，以关键问题选择专项，另一项由Editor在职责内处理，不自动升级五人。
- 第四位默认写后参与；只有明确写前缺口且本地补读无法解决时才提前参加，结果交Writer复用，不每章固定两次专项调用。
- 节省与平衡处理硬矛盾，以及影响剧情理解、人物动机和关键转折的实质问题。无硬错的集中修改先问作者，其他优化留给作者选择。
- 高质量还关注明显阅读体验改善，仍须先询问是否修改。小幅换词或模型评分略增不触发额外调用。
- 平衡更充分准备与必要修复均保留，但重点在主线、关键因果和重要人物变化，不追求全面精修；额外调用只对应实际重要缺口，不固定追加轮次。

## 实施与观察边界

协作选择、旧快照恢复、限定职责、重试次数须从真实接口验证，不能仅凭提示词宣称完成。协作冻结与Provider重试已有离线契约检查；高质量已从已有检索排名读取相关历史全文，核版本、去重并与历史缺口回源共享六来源及40,000 token补读上限。全文未装入会保留原因，不能把片段读取说成全文已读；读取不代表语义已正确采用。节省对普通软参考最多使用6,000 token，必要正史、点名全文、设定和用户锁定资料不由该额度删除。

源码已接通实质建议选择卡：原审查的动机、剧情推进项为明显薄弱（grade≤2）且原句可定位、证据关系已明确时，节省和平衡可提出一次局部修改；高质量额外采纳同等级的阅读改善。轻微弱点、未定位引文、资料不足及纯评分增加不触发卡或固定调用。批准绑定原任务、配置、当前稿件、报告和参考来源，沿原恢复次数局部修改并由原责任角色复核；中断计次，不自动再做同一次润色。保留当前稿时只复用仍有效的通过报告，未通过的稿件不因选择而放行。单章验收、批次记忆暂存及后章写作、连续写作均先等待该选择，原批次范围保留。

高质量的复杂章讨论建议由同次Coordinator输出planning_discussion提出，代码先保存来源并给出“按现有规划直接写作／先讨论本章小规划”。直接写作复用原任务，不增加独立规划调用；讨论先保留目标与范围，待作者说明想要的结果。来源改变后旧选择失效。这里接通的是讨论入口，不表示已有自动生成、审核和发布独立章节小规划的新工作流。
