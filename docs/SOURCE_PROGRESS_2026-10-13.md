## 缓存与验证口径

缓存命中率按供应商已报告的 `cache_hit_tokens / input_tokens` 计算，失败与返工调用纳入对应批次。未知 usage 单独记录，不算零；不发送付费预热请求，也不通过保留无用材料提高分母。旧异常产生的消耗不能从本批累计数中删除。

DeepSeek 当前缓存要求复用已经持久化的相同前缀，并采用尽力复用机制，不能保证每次调用达到某个比例。[官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache)。本次查明连续Writer输入在前段事实选择处已分歧：同一已授权批次的实际章节卡合并为稳定事实查询，当前章检索仍按本章；稳定设定和伏笔放在追加临时正文之前。仅参考性的历史片段按Writer预算筛选，正史事实、用户要求、设定和点名来源不因此裁剪。表达定点修订保留当前稿、当前报告、要求、设定、章节卡及声音，不重复全套长历史；有事实问题仍用完整依据审查。没有增加付费预热调用；80% 仍须由供应商实际回报核对。

基础技能采用明确示例作为生成条件，没有修改供应商的Transformer权重。[Few-Shot研究](https://arxiv.org/abs/2005.14165)支持推理时使用文本示例；[长上下文位置研究](https://arxiv.org/abs/2307.03172)研究的是问答与检索，不能拿来证明小说文风已改善。这里把简短技能引用与当前任务相邻，实际效果由正文、同依据审查和作者反馈核对。

已完成与本次故障相关的 Python 解析、实际草稿的无语义格式检查和桌面 TypeScript 检查。实际样本中，已通过的第46章不发生格式变化；第47章只增加一对引号。其篇幅调整参考包由约29万字符缩到约5.8万字符，这个体积对照不等同于已测得的供应商费用或命中收益。

语音的组件／模型就绪判定已核对；没有代用户录音，没有宣称所有设备实测完成。自由窗口布局、动画观感、文风满意度和最终缓存收益仍以真实体验为准。没有执行全量回归、安装包重编译或额外付费基准测试。
