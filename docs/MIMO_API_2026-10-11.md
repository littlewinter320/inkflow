# 小米 MiMo API 适配 — 2026-10-11

本次为源码适配，未安装新版、未调用真实收费接口。复用现有 OpenAI 兼容适配器、系统凭据、配置快照、调用预算、JSON 校验和用量账本，没有新增模型 SDK 或另一条小说运行线。

## 配置与当前型号

- `provider_kind: mimo`，默认基础地址 `https://api.xiaomimimo.com/v1`，默认 `mimo-v2.6-flash`。可选择 `mimo-v2.6-pro`；`mimo-v2.6-pro-ultraspeed` 属定制服务，实际资格以账号为准。
- 普通按量使用普通 `sk-` 密钥。Token Plan 使用 `https://token-plan-cn.xiaomimimo.com/v1` 以及个人 `tp-` / 团队 `ttp-` 密钥。已知地址与凭据用途不匹配时，发请求前拒绝并给出正确入口，不显示密钥。
- 新服务商使用 `MIMO_API_KEY` 或现有 `provider:mimo:api_key` 系统凭据；`INKFLOW_API_KEY` 仍有更高优先级。导入、手动配置和连接检查复用现有 RPC；保存配置不会自动检查连接。
- `mimo-v2.5` 与 `mimo-v2.5-pro` 于北京时间 2026-10-21 10:00 下线，不设为新默认；不改写旧任务快照或原角色选模。

依据：[首次调用 API](https://mimo.mi.com/docs/zh-CN/quick-start/summary/first-api-call)、[模型列表，2026-10-08 更新](https://mimo.mi.com/docs/zh-CN/quick-start/summary/model)。

## 调用契约

Chat Completions 使用 `max_completion_tokens`，范围为 1～131072，包含推理与可见输出；重试仍用同一字段并重新扣除完整输入。`thinking.type` 明确设为 enabled 或 disabled。MiMo 不发送 DeepSeek 的 reasoning_effort、未声明的 top_k 或 OpenAI 的 prompt_cache_key。连接检查沿用 160 token、明确关闭思考、每次至多 60 秒的短 JSON 请求。

MiMo 非思考采样温度范围 0～1.5、Top P 范围 0.01～1；越界在发请求前说明，保留保存值供用户纠正。思考开启时按服务端契约使用 1.0 / 0.95，能力描述公开此约束；格式修复关闭思考后恢复有效角色采样。原调用及重试仍计入同一个 RunRuntime。

官方模型页将上下文写为 1M，源码保守采用 1000000；精确输出上限采用 131072。能力仅为明确官方域名和已核文本型号记录；代理和未知型号不继承这些预算。

`response_format: json_object` 继续由本地 Pydantic 验证必填字段，JSON 模式本身不保证业务 Schema 完整。MiMo 参数错误不触发移除 JSON 模式的无条件 400 / 404 / 422 重试；原格式及网络补救仍限次执行。没有新增服务端 json_schema 或推理强度分档承诺。

依据：[Chat Completions](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api)、[模型超参](https://mimo.mi.com/docs/zh-CN/api/guidance/model-hyperparameters)、[结构化输出](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/structured-output)。

## 用量与扩展

继续消费 prompt_tokens、completion_tokens、total_tokens、prompt_tokens_details.cached_tokens 及 completion_tokens_details.reasoning_tokens。缓存缺字段保持未报告，推理数量不重复加入输出总数。不新增未经核实的缓存控制字段或固定命中率目标。[官方 Chat 用量字段](https://mimo.mi.com/docs/en-US/api/chat)、[缓存计价说明](https://mimo.mi.com/docs/zh-CN/price/pay-as-you-go)。

扩展的手动配置与 JSON / JSONC 导入支持 mimo，手动入口说明按量与订阅地址。裸 tp- / ttp- 与 sk- 凭据均纳入脱敏；不导入提示词、MCP 或权限。检查连接仍需用户明确触发，最多三次短请求且可能计费；刷新配置和诊断不发模型请求。

## 验证边界

`agent/scripts/check_mimo_api.py` 使用 httpx.MockTransport 和 D 盘临时配置、账本，覆盖默认配置、官方型号/主机预算、未知型号与代理、凭据用途、模型枚举、思考/采样、短检查、格式恢复、固定任务预算、完整输入约束、400 停止和缓存缺失。`extension/scripts/check-workbench.cjs` 加入 MiMo 导入、地址与凭据匹配及订阅凭据脱敏断言。

## 生成侧审查归因契约

当前审查提示词要求每项 assessments 和 source_comparisons 明确 evidence_relation，但存储模型为读取旧报告保留默认 unchecked，直接将存储 Schema 发送给模型会使该字段被标为可选。此次只在发送给模型的 Schema 投影中，将 ReviewAssessment / ReviewSourceComparison 的 evidence_relation 标为必填并移除默认值；OpenAI 兼容（含 MiMo、Ollama）与 Anthropic 共用该投影。旧记录读取、分类值与证据门禁均不改，未定位的 OUTLINE / RECENT_PLAN 引文仍需核对，耗尽的原任务不会因此重试。

相关最小断言为 `agent/scripts/check_review_generation_schema.py`：比较实际模拟请求中的完整 Schema，同时确认旧报告缺字段仍读取为 unchecked，生成投影稳定且不污染原 Schema。没有自动补分类或把未知报告改成通过。

2026-10-11 实际执行一次通过：OpenAI、Ollama、MiMo、Anthropic 四个模拟请求均发送同一份必填归因 Schema；旧对象缺字段仍为 unchecked。未发真实请求，未修改章 31 报告或原任务尝试记录。
