# 接口与后台偏好学习修复

本记录区分源码修改与真实运行效果。当前源码仍为0.7.5，本次未安装软件、生成安装包、发布新Release或改变供应商模型权重。小说私稿、用户样稿、费用账本和API凭据不进入仓库。

## 查明并修正的接口问题

| 触发情况 | 原问题 | 源码修改 |
| --- | --- | --- |
| MCP普通文件写入或删除 | 绕开文档版本与正史保护；删草稿不改数据库状态，永久删除还能命中整目录 | 复用Studio安全保存和单文档删除；正文只建立未应用提案，删除同步草稿状态，通用入口不执行永久删除 |
| MCP文档手动保存 | `mcp_editor`没有进入手动修改核对，而被当作引擎写入 | 与桌面手动保存使用同一后台核对入口 |
| 通过含`./`或`../`的项目内别名保存正文 | 实际文件相同，保护判断却使用未归一的文字路径，可能漏识别已接受正文 | 读取、保存、批注、删除及保护判断先取得项目内真实相对位置 |
| 给已接受章另存同章草稿 | 文件先写入，随后数据库拒绝把正史降为草稿，留下失败产物 | 在文件写入前核对章节状态并拒绝该覆盖方式 |
| 桌面预填前出现Emoji或扩展汉字 | 编辑器用UTF-16位置，Python用Unicode字符位置，光标附近文字错位 | 桌面先转换字符位置，再请求预填并核返回位置 |
| 预填期间正文或参考更新 | 仅核输入字符串自身，缺少当前草稿和资料身份；预填也没共用完整默认表达技能 | 请求前后核真实草稿、版本、内容及规划/设定指纹，共用内置表达规则和匿名示例，并核完整输入容量 |
| 扩展中打开另一作品的同章号文件 | 只从文件名抽章号，实际审查了当前工作区的另一章 | 先核当前项目内的托管章节位置 |
| 提示词优化采用角色选模 | 没有指定协调角色，绕开Coordinator专用模型配置与用量归属 | 在冻结配置内绑定Coordinator，仍是辅助工具，不产出章节审查覆盖 |
| 作者设置暂停学习后保存整个设置 | 另一个学习开关把打开设置时的旧值写回，重新开启学习 | 删除重复设置入口及保存逻辑，作者习惯页即时开关作为唯一入口 |
| 学习奖励传入NaN或比较不存在的记录 | 无效数值可能被夹成满分；偏好对没有真实候选来源 | 拒绝非有限数值，比较须为同用途、责任角色、章节的两份真实候选 |
| 多维预审输入没有合法方向 | 返回空报告却没有说明没有执行审查 | 模型调用前拒绝空审查方向 |
| 不含偏好反馈的普通对话 | 新增条件分支中的重复导入把共享偏好函数遮蔽为局部变量，路由返回后无法续接 | 删除局部重复导入，统一使用模块入口；真实设定体检暴露此问题后修复，并检查该方法内无同类导入遮蔽 |
| 整批续写同时指定局部修订及正史保护范围 | 最后出现的“第1—45章正史不动”被当作创作对象；整批范围被子步骤替代 | 同时识别范围前后的保护说明，明确的整批目标容纳局部范围，不据此扩大独立修订范围 |
| 设定体检已经更新并核对条目 | 旧手动核对任务仍显示依据不足，后续再次建议处理它 | 待办及手动核对面板读取时核当前条目、合集和真实来源；仅已有核对通过后继版本的旧任务标为失效，保留原失败记录及次数 |
| 普通界面展示原始JSON、哈希和路径 | 数据存在，但缺少面向作者的显示适配 | 作者习惯、结果详情、记忆预览、检索及运行记录使用按真实字段生成的自然语言；原始记录保留在后台 |
| 当前规则允许正常标点，审核却称顿号禁用 | 回归指标仍保留旧的无条件警告，和当前确定性审查相互矛盾 | 删除无条件警告及局部修订中的通用禁用提示，是否违反标点要求由本书实际规则判断 |
| 报告只有普通表达问题却判核心要求未满足 | 直到完整来源补读后才发现报告自相矛盾 | 生成解析时拒绝缺少硬问题依据的必需项失败，交原模型在已有纠错预算内修正；历史报告保持可读，代码不改成通过 |
| 新文风任务中途恢复 | 全局指令被标为相同，未走到的旧草稿也跳过了新要求 | 逐章核对当前正文及审查所绑定的指令；未处理新要求的后续旧草稿仍进入定点修订，已核对当前要求的前序不重放 |

## 采用的研究思路

NVIDIA参与的[Voyager项目](https://voyager.minedojo.org/)结合环境反馈、执行错误、自我核验与可复用技能库，并通过黑盒模型调用工作。其实验任务是Minecraft，不能把游戏结果写成小说质量收益。本次借鉴的是有据反馈、验证后再复用方法的结构。

[NVIDIA关于Agent强化学习的技术文章](https://developer.nvidia.com/blog/mastering-agentic-techniques-ai-agent-reinforcement-learning/)区分提示、检索、偏好训练与可验证奖励，并强调验证器和真实结果的重要性。墨流当前使用供应商模型API，因此本次采用应用层的经验与偏好选择，不宣称进行了RLHF、DPO、GRPO或权重训练。

[NeMo Agent Toolkit的评估文档](https://docs.nvidia.com/nemo/agent-toolkit/latest/improve-workflows/evaluate.html)把工作流质量、可靠性和耗时分开衡量。本次继续复用墨流已有的正文证据审查、接受回执与运行费用统计，不额外安装评估平台或启动付费基准。

[NVIDIA Data Flywheel仓库](https://github.com/NVIDIA-AI-Blueprints/data-flywheel)在读取时已注明2026年4月停止维护。本次只参考反馈闭环思路，没有引入该框架或照搬其部署方案。

## 后台学习怎样接入

1. 同次Coordinator输出提取具体的认可、纠正目标或对已有习惯的否定。普通命令、接受正文、机器通过、沉默与笼统“不错”不产生满意加分。快速续接绕过模型路由时，仅实际需要理解具体反馈且预算/禁止项允许，才条件式调用一次现有Coordinator；不会重新选择批次或扩大权限。
2. 代码核对用户当前原句及已有条目身份。否定已有习惯须核该条目的ID、修订与原文；对错误输出的不满，应提升希望采用的具体改法，不能误扣改法的分数。
3. 复用本机学习事件，按偏好内容、范围及层级指纹绑定信号。同一句同一方法去重；修改偏好文字或范围后旧分不迁移。停用条目不恢复，候选不因反馈数量升级确认状态。
4. 明确认可记1个信号，具体纠正目标记0.5，对已有偏好的明确否定记-1。累计权重限定在-1至1，只在确认状态和适用范围相同的普通声音参考之间排序；硬要求、正史、来源和接受权限不受积分影响。这是有限的选择偏好，不是质量概率或模型奖励训练。
5. Writer、审查及记忆责任角色继续通过同一上下文服务消费适用偏好；8,000 token的普通声音参考预算保持。技能选择只记录最终实际装入的名称，装入不冒充正文已正确采用。
6. 失败修订使用现有差异与完整审查，记录是否改了原文、残留的同一证据问题、问题类别及实际结果。未解决结果给方法提醒，不能被记成成功；当前来源、角色、次数与权限仍核验。运行时不自行改源码、降低门槛或永久增加禁令。

学习不固定增加每章反思模型，不逐次弹窗，不在普通对话通报积分，也不展示学习计数卡。用户仍可在作者习惯与记忆中查看、修改、停用或暂停。真正适用的硬要求互斥或长期范围不明确时，才通过原任务提一个必要问题。

## 检查与仍待观察

静态调用审查覆盖44个引擎Python模块以及1,177处直接引擎、项目、数据库与记录调用；桌面通信入口与处理端、前端请求方法均检查对应关系。此统计不表示每条分支已经真实运行，也不代替功能验证。

桌面及扩展TypeScript检查通过，相关Python源码解析通过。没有执行全量回归、安装包重编译、NVIDIA部署或额外付费模型基准。真实小说中的后续偏好采纳、满意度、错误复现率、调用消耗及80%缓存目标仍须观察实际产物与供应商回报，不凭代码或模型自报宣布达标。

真实界面的设定体检已完成一次责任角色调用并保存两份有据更新。报告读取条数与库内总数不是同一统计，不能由数字差推断新建了重复记录。章节请求的保护范围误判已用五个针对性离线输入检查，包括整批下的子范围、参考前章、前置/后置保护及仅修旧批次的一部分；此检查不代表小说批次已经完成。

后续真实运行已完成第46—50章并按连续前缀验收，界面显示50章正史、0章待核/待接受。新版设定核对接管了旧手动候选，相关已完成章节任务随接受结果收尾。旧恢复方案保留原失败及尝试记录，不能用验收结果宣称所有历史诊断都成功。

本批从开始处理到接受的供应商账本共26次请求（包括3次失败及其纠正），输入2,864,103 token、缓存命中2,014,848 token，加权命中70.35%，尚未达到80%。Writer表达修订单次输入约1.96—2.00万token，较此前约17.56万的局部修订输入明显减少；这不表示整批总费用已经同比降低。后续推荐输入同步提供最近已接受章节和剩余草稿，并把可选旧恢复记录与必要待办分开，避免把可选历史误称为当前写作阻塞。

缓存诊断对照实际连续审核输入，确认约28,929字符的设定与伏笔块完全相同，却排在变化的临时记忆之后。源码已把所有批次责任角色的这两块资料放到临时记忆之前；仅调整呈现顺序，仍按当前章、角色与来源读取，不扩大召回或将参考升级为正史。该顺序修复在上述批次结束后交付，尚未用下一批付费请求测量收益。

主要修改入口：`mcp_server.py`、`studio.py`、`app_server.py`、`terminal_session.py`、`preferences.py`、`learning.py`、`context.py`、`database.py`、`trace.py`及桌面/扩展的显示和编辑器入口。
