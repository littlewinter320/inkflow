# 本书设定：基础、高级、动态记录与审查

这是 0.7.5 的源码增量，不代表已发布新安装包。

## 问题与证据

实际项目存在结构化规模已改而当前用户规则仍保留旧篇幅要求的情况；这不是正文自动违反设定的证明。还存在只有字段模板、没有具体条目的合集。真实观察中，一次要求检查一致性的对话只列出合集，界面却泛称工作流完成；这些都不能作为已审查的证据。

同次 Writer 和审核输出允许 setting_updates，但提示词只鼓励“新创作设定”，且审核角色只补已有条目，空合集容易长期没有首次记录。接受时还需把同版草稿引用转换为已经接受的正文身份。

## 当前接口与职责

| 层 | 输入与职责 | 保存与限制 |
|---|---|---|
| 基础设定 | 默认人物、世界，首次打开时只补建两个空模板 | 不伪造人物或世界内容；模板不算审查通过 |
| 高级设定 | 从现有模板或自定义字段新增；可编辑记录说明/提示词 | 每项持续记录开关；删除移出当前使用并保留历史引用 |
| Writer | 读取适用条目和当前要求；同次交稿提出首次建档、变化与补充候选 | 不覆盖已核记录、不提交正史 |
| 主审 | 对实际装入条目返回适用性、设定原句、本章原句与理由 | 空模板不假装有内容；缺依据走原有有界补核，不把漏读交 Writer 改稿 |
| 当前记忆责任角色 | 在已有调用中提取需持续维护的人物、世界或已开启高级设定 | 首次参考建档须有正文，区分客观记录、信念、传闻；不另创新剧情 |
| 引擎 | 核对权限、开关、记录版本、来源版本及原句，按接受流程保存 | 同一交接幂等；关闭自动记录不能被模型写入；正史仍走独立提交门禁 |

持续维护按章节接受事件进行。没有变化不保存新修订，也不增加定时轮询模型。普通开关、名称等管理修改不使整合集语义复审失效；记录说明、字段或角色权限变化才重新核对相关记录。已有记录在关闭自动维护后仍可读取、核对；手动编辑仍可用。

设定是四种不同对象：书籍要求、合集模板、带出处的具体参考、已接受正文中的正史。模板字段和提示词不是事实；审查通过只证明参考可用，不赋予用户同意或正史提交权。

## 自主检查入口

`story_settings_manage` 的 `audit` 操作由当前责任角色读取书籍资料、当前三层规划、最近三章及近期规划点名前史（合计最多六章）以及有界事实/伏笔，不让 Coordinator 仅凭概括替代审查。用户要求处理时，可返回有当前原句支持的旧规则纠正，代码检查唯一旧规则及来源后走已有版本保存、手动变更复核；来源变化不写回。具体设定提案只能使用本次确实读取且仍有效的正文。此入口不代表逐章审完整本小说。

后续真实观察要分别记录：模型发现的问题、自动写回的修订、未完成或需选择的事项、实际记录数与来源。不能把调用、模板数量、模型自称完成当作成功。

## 针对性检查

本次明确获用户授权进行设定测试。共覆盖十七个针对性离线用例：空字段拒存、空模板状态、逐条原句对应、权限过滤、失效来源、角色边界、基础项初始化幂等、高级开关拦写、关闭开关不误触语义复审、规划漏审不放行、冻结配置恢复、修正依据定位、真实服务保存/复核/再读取，以及章节接受后证据转换和重复交接不增版。部分用例包含多个相关断言。

修改后的桌面 TypeScript 检查通过。没有运行全量回归，没有安装或发布新版。真实小说自主识别与整改效果另按实际运行结果追加，不能用离线用例代替。

## 真实检查观察（进行中）

第一轮普通中文请求进入 Editor 的设定检查，模型自行指出规模冲突和三个空合集，提出八条有据建档候选；但旧规则未完整定位导致当轮写回失败。这轮未保存条目，不能写成成功。随后修复：从当前会话传递已确认用户要求，回读近期规划点名的已接受前史；旧规则定位失败只影响该修正，不取消独立的有据条目。保留原失败与自动恢复次数，不重置。后续以实际写回与来源为准。

审查与设定共用记录ID、修订号及来源。章节报告的 setting_checks 由设定页只读关联展示，修改条目、正文或来源后旧结论标为历史；不会复制一份互不更新的设定。关联报告不重复装入模型资料。需要选择时复用现有结构化问题卡，给具体方案、影响与推荐；纯自由输入不再显示孤立的“其他”单选。

第二轮已自行识别用户确认的篇幅要求，并回读第41章纠正第一次的章号疑问。三个新建档候选的引文实际存在，但入口没有复用 source_chapter 的兼容解析、用户原话也没注册来源ID，仍未写回。已改为共用现有证据解析服务，并登记当前对话中的用户原话，避免将模型回复当用户授权。此处保留失败证据，不写成已完成维护。

后续真实运行已通过应用把当前书籍要求同步为既定规模，旧版由版本服务保留。该次后续核对遇到瞬时项目写锁，尚未保存具体设定条目。已将异步手动核对改为等待短锁、把书籍保存和核对登记放在同一协调区间，并对有据条目的写回单独协调；离线竞争检查确认不会因为另一个短写入立即失败。设定报告的输出预算改用现有角色/模型能力及资料规模计算，问题与引文精简，稳定资料置前；截断运行仍记失败，未伪造成功。

证据提案已从任意字典改为共用的类型结构，明确来源类型、章号/路径、原句、关系及可选版本。历史 source_chapter 数字、章节来源ID及当前文档名称在入口适配；新旧身份冲突拒绝，不把文件名当章号。需要依据的部分统一归为等待条件，不能因未知状态字面值而显示整项完成。

真实应用已保存并核对通过首批五条设定，每条两处原文依据；对应基础人物四条、高级地点一条。设置页实际显示了人物/世界基础组、高级组和持续记录开关。世界条目遇到已是当前值的规则变更返回值，现已修复无变更收尾；其他未定位候选改为同责任角色一次合并补核，只重传失败对象，禁止额外调用时不补核。有效候选不重生成，不追加外围Coordinator恢复。前次读取数、本次保存数与当前总记录数分别展示。内容未变的重复维护不增加修订号。尚未把残留引文问题写成全部解决。
