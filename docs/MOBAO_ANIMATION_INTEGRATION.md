# 墨宝窗口内动画、结果引导与接口接入规划

日期：2026-10-09。状态：用户已确定“在墨流窗口内走动，指向已完成的任务和文件”；0.7.4 已接入前五段透明动画及窗口内的移动、指向、摘要展示、返回退出流程。默认自动展示摘要，真实文件由只读按钮打开；未收到的专用移动/指向视频仍按下文记录规划。媒体验证见 MOBAO_ASSET_INTAKE_2026-10-09.md，应用完成链的观察范围见 RELEASE_0.7.4.md。

## 现有依据与形象参考

- 形象参考：[墨宝原始标志](../desktop/src/assets/mascot/mobao-logo-original.png)。米白色球形身体，黑色宽沿帽，帽上橙金火焰，琥珀色大眼睛，黑色盘绕钢笔和金色笔尖。不得凭想象添加人形手脚或换脸。
- 当前动画入口：[Mascot.tsx](../desktop/src/Mascot.tsx)，已有 idle、thinking、waiting、success、rest、welcome、reading、writing、reviewing 九种 mood；视频失败和系统减少动态效果均有静态图降级。
- 任务结果与文件入口：[App.tsx](../desktop/src/App.tsx) 的 sendChat、processRuns、LiveRunTimeline 与 onOpenReference；前台读取实际返回状态和公开文件引用。
- 当前独立对话有 conversation_id。动画只属于其接收结果的窗口，不得跨对话、跨书打开产物。
- 模型的“完成了”文案不构成触发凭据；引擎任务状态、文件存在与来源版本共同决定可展示结果。

## 首期适配和接口逻辑

首期复用当前 Mascot 与文件预览处理，不做操作系统鼠标控制，不建立新模型或额外费用流程。缺少的专用动作使用现有 mood 静态回退或容器位移。动画元数据、结果开关和移动控制须由前端确定，模型不得输出选择器、坐标、命令或任意 URL。

后续需要多结果列表时的扩展建议（当前没有新增此结构）：

```ts
type MobaoCue = {
  cueId: string;             // runId + action + verified result identity
  runId: string;
  conversationId: string;
  projectRoot: string;
  action: "welcome" | "idle" | "thinking" | "writing" | "reviewing"
        | "move_right" | "move_left" | "point_result" | "tap_result"
        | "show_summary" | "waiting_user" | "pause_exhausted";
  target: "chat_result" | "document_result" | "review_result" | "pending_work" | "home";
  summary: string;           // plain text from visible result, never HTML
  references: TraceReference[]; // reuse existing verified local references
};
```

当前实际接口为 Mascot.tsx 的 MobaoGuideCue {id, summary} 和 MobaoGuide，接收工作区、目标及停靠元素引用、只读预览callback和disabled条件。App.tsx 保存本次完成回复ID、run ID和项目身份；只从本次完成步骤获取存在的产物引用，不接受模型提供的坐标、选择器或任意URL。上面的扩展结构保留为建议，不能当作当前运行合同。

结果自动展示条件：

1. 只有明确 completed 事件及已核实的实际产物才进入完成引导；waiting_user、waiting_condition、failed、cancelled 分别展示原因和已有进度，不播放“任务全部完成”。
2. 点击完成项调用现有结果预览处理函数。允许打开已完成草稿、审查报告、规划或运行详情；接受正文、发布规划、删除、上传、设置、支付等动作不属于此接口。
3. 有多个文件时展示一张结果清单；首个可预览产物可在用户未编辑、未选区、无模态框且项目仍一致时自动打开。否则墨宝指向“查看结果”按钮，由用户打开；保留未保存输入。
4. 用户正在读别的文档或关闭自动展示时，只保留完成卡和轻提示。打开结果失败保留原文件入口和错误说明，不重新运行任务。
5. 已标为历史、superseded 或来源变化的结果只显示身份及说明，不使用旧事件自动切换当前正文。

## 移动边界与互动收尾

- 活动范围是当前墨流工作区内框，排除标题栏、模态框、正文选区、编辑输入、底部输入框和关闭按钮；用户拖动或窗口缩放后重新测量目标。
- 移动代码控制世界坐标，视频只表现墨宝原地漂浮的移动动作。用容器 bounding rectangle 和目标 anchor 计算并 clamp 坐标；禁止把整段移动烘焙进视频后再次位移。
- 每个窗口最多一个引导。状态为 idle → move → point → present → return → idle；超时、用户打字、切书、目标消失、停止任务、关闭窗口均退出并清理计时器。
- 一次引导总计最多 8 秒；到达提示位置后 3 秒内收尾。用户明确打开的结果详情可继续保留，但墨宝不永久挡住控件。
- cueId 去重；晚到的旧 run 不覆盖新任务。连续多个完成事件合并成一次展示，不循环播放成功动画或不断点开同一文件。
- 视觉层默认 pointer-events:none；只有结果按钮可以接收操作。移动使用 transform；键盘焦点始终留在用户原输入，不靠模拟鼠标点击操作业务。
- 系统 prefers-reduced-motion 开启时用静态指向和结果卡；视频缺失、损坏、无法解码时立即回退当前静态图。后台窗口不持续播放高频动画。
- 带来源变化或次数耗尽的待办走 waiting_user / pause_exhausted；动画结束不关闭待办、解除门禁或清空失败记录。
- 需要使用结果引导的自动点击只读入口时，在任务开始之前用明确设置启用；首期默认自动展示清单并允许一键预览，是否默认自动打开首个文件需在实际体验后确定。

## 12 个素材位、触发位置与视频提示词

统一生成前缀：以墨宝原始标志图片为唯一角色参考，保留米白球形身体、黑色宽沿帽、橙金火焰、琥珀眼睛、黑色盘绕钢笔和金色笔尖；精致柔和的 3D 玩具质感，固定正交镜头，稳定比例和轮廓，无人形手脚，无字幕、文字、UI、额外角色、镜头推拉或场景转换。每条动作与下面的统一前缀一起提交。角色占画面约 65%，火焰完整不裁边，影子不能出现背景色块。

| action / 文件名 | 触发及位置 | 时长 / 循环 | 回退 |
| --- | --- | --- | --- |
| welcome / mobao-welcome.webm | 首页打开，欢迎区 | 3 秒 / 单次 | welcome poster |
| idle / mobao-idle.webm | 对话栏角落待机 | 4 秒 / 循环 | idle poster |
| thinking / mobao-thinking.webm | 理解任务，输入框附近留白 | 3 秒 / 循环 | thinking poster |
| writing / mobao-writing.webm | Writer 已实际开始，编辑区外侧 | 4 秒 / 循环 | 当前 writing 图或 sprite |
| reviewing / mobao-reviewing.webm | 当前责任角色核对，审查区旁 | 4 秒 / 循环 | reviewing 图 |
| move_right / mobao-move-right.webm | 去往完成卡，沿右侧留白 | 2 秒 / 循环 | idle 图配容器位移 |
| move_left / mobao-move-left.webm | 引导结束回到停靠点 | 2 秒 / 循环 | idle 图配容器位移 |
| point_result / mobao-point-result.webm | 完成卡/真实文件按钮边缘 | 2 秒 / 单次 | success poster |
| tap_result / mobao-tap-result.webm | 已完成结果的只读预览入口旁 | 1.5 秒 / 单次 | 静态指向 |
| show_summary / mobao-show-summary.webm | 运行台或聊天完成摘要旁 | 3 秒 / 单次 | success poster |
| waiting_user / mobao-waiting-user.webm | 绑定待答卡旁 | 3 秒 / 循环 | waiting poster |
| pause_exhausted / mobao-pause-exhausted.webm | 预算/次数耗尽或暂停的待办卡旁 | 3 秒 / 单次 | rest poster |

1. **欢迎**：墨宝从略低的位置轻轻浮起，眼睛慢慢睁大，帽顶火焰柔和亮起，向观众点头两次，钢笔笔尖轻抬表示欢迎，最后平稳停在中心。开头安静、结束稳定，动作温柔克制。
2. **待机**：墨宝在中心轻轻上下漂浮，身体幅度很小，偶尔眨眼，帽顶火焰缓缓摇动，钢笔保持原姿态。首尾姿态及火焰相位衔接，无突然转身，适合无缝循环。
3. **理解任务**：墨宝轻歪帽子，眼睛从左到右缓慢观察，好像认真听用户讲话；笔尖轻轻绕一个小圈，火焰起伏一次，再回到开始姿态。表达思考但不焦躁，无缝循环。
4. **写作**：墨宝略向前倾，金色笔尖在身前小范围平滑书写，浮现两三条很淡的金色墨迹随后消散，不形成可读文字；眼睛专注，帽顶火焰随动作轻动，最后回到初始书写姿态。
5. **审读**：墨宝低头逐行阅读两张无文字的半透明空白纸页，眼睛从上到下移动，笔尖轻点其中一处，微微点头；纸页数量固定，首尾衔接，表现细致核对而非批改惩罚。
6. **向右移动动作**：墨宝保持画面中心，侧身朝右，身体做轻盈的漂浮行进动作，火焰和盘绕钢笔略向左后方摆动，眼睛看向右前方；角色没有画面内水平位移，首尾一致，供软件控制整体移动。
7. **向左返回动作**：墨宝保持画面中心，侧身朝左，放松地漂浮行进，帽顶火焰轻轻向右后方摆动，眼睛看向左前方；金色笔尖始终保留正确侧别，不用简单水平翻转替代重新生成，角色无画面内水平位移。
8. **指出已完成文件**：墨宝先看向观众，再转向右侧，金色笔尖稳稳指向右边的空白目标区域，身体轻轻点头，火焰闪亮一次。右边留出 30% 空间给软件按钮，动作结束保持指向 0.5 秒。
9. **轻点结果入口**：墨宝抬起金色笔尖，朝右下方空白区域做一次清晰而温柔的轻点，小小金色圆环瞬间出现并消失，墨宝随后抬眼确认。整个动作只点一次，无真实按钮和文字，结束回到稳定姿态。
10. **展示完成摘要**：墨宝身旁浮出三张无字小纸页，笔尖依次指过，纸页短暂出现简洁金色光点；墨宝最后看向用户并轻轻点头。不要生成完成文字或虚假软件截图，摘要由软件单独呈现。
11. **等待用户决定**：墨宝安静停在左侧，留出右侧空间放提问卡，钢笔收回一点，眼神专注看向观众，轻轻眨眼并做一次小幅点头；火焰保持低幅度摇动，不挥动催促，无缝循环。
12. **停止重试并交接**：墨宝把笔尖平稳放下，帽顶火焰降低亮度但不熄灭，轻轻呼一口气，抬眼指向右侧空白说明区，最后回到安静待机姿态。表达“进度已经保留，先补条件”，不摔倒、不哭泣、不爆炸、不假装成功。

## 输出与保存

优先交付透明背景 WebM（VP9 alpha）以及同尺寸透明 PNG 首帧，建议 512×512、24 fps、单段不超过 4 秒。若生成平台不支持透明通道，另交付无色溢出的纯色背景母版到 D:/墨流/media-source；不要声称已透明。素材清理、转码和 alpha 检查在接入前独立处理，不能直接把绿色背景视频放进界面。

源码采用素材保存到 desktop/src/assets/mascot/animations。原视频与生成母版保留 D 盘专用目录，不覆盖用户已有素材；真正采用某段之后才替换对应资源并检查最小范围。poster 和 video 的形象、方向、尺寸必须一致。
