# 墨流（InkFlow）0.3 发布说明

0.3 的目标是把 0.2 的核心引擎整理成更接近可发布软件的版本：完全没有想法也能建项；自然对话遇到真正分岔时可以用提问卡确认；写作资料可以先联网搜索再选择导入；桌面端与 VS Code 都有中文工作界面。

## 用户可见变化

- “三个方案无法继续创建”已修正：三个模型方案即使返回重复编号，宿主也会重建稳定编号；每张方案都有明确的“采用这个方案”，采用后自动填入可编辑建项信息。
- 新建小说显示“选目录—构思/填写—确认创建”三步，并在底部直接说明还缺什么。
- 模型设置提供专业均衡、稳健连载、灵感探索和节省模式四个预设；原有字段仍可手调，单次输出上限固定 16K。
- 项目中心直接显示当前卷、当前篇章和连续章节卡，章节功能与章末钩子可以逐张查看，也能一次预览整篇规划。
- 自然对话返回结构化提问时弹出独立提问卡。每题展示提问原因、单选/多选、选项影响与最后固定的“其他”。用户也可主动要求墨流先提问。
- 参考资料页新增公开搜索：先预览标题、摘要和域名，只有点击“导入这页”才保存网页。
- 过程页继续只展示任务计划、公开判断与状态，不展示或保存模型原始思维链。
- 新增“检查更新”界面：配置公开发布源后，可检查、下载并在重启时安装新版；私密阶段会明确说明尚未配置，不会要求普通用户填写 GitHub 令牌。

## 写作质量与 Token

- Writer 与修订模式启用“自然中文正文”引导：场景目的和因果优先，保留人物声线，交付纯正文，不用禁词表把作品磨成同一种声音。
- 新增“连载结构、钩子与伏笔”技能：四级规划必须维护短线钩子、中线伏笔与长线承诺；伏笔区分种下、推进、转义、兑现和延期；钩子由本章后果自然产生。
- 新增“写作资料研究”技能：面向写作教学、职业知识与心理学等资料，先缩小问题、核对来源，再转换成适用场景、写法和边界。
- Context Builder 使用本地轻量 BM25 风格排序召回相关旧章摘要；最近章节仍保留全文，久远内容按任务相关性进入上下文。
- 每章最多注入两条与题材和章节卡相关的技法提示，不增加模型调用；常规章节不会自动联网。

## VS Code 0.3

- 左侧新增中文“创作主控”：项目指标、章节号、规划、写作、审查、验收、自然语言和工具入口集中在一个视图。
- 结构化提问使用 VS Code 原生单选/多选框，并在选择“其他”后打开自由输入。
- 补齐商店介绍、墨宝图标、更新记录、支持文档和四步入门引导。
- 保留小说结构树、选区批注、定点修订、章节审查、检查点、任务记录与 MCP 合并配置。

## 联网能力与外部依赖

`novel_reference_search` 使用可替换的 `duckduckgo_html_v1` 公开搜索适配器。它只发送搜索词，不发送小说正文、正史、项目文件或模型密钥；搜索结果也不会自动进入资料库。该能力不需要付费搜索 API，但依赖公开搜索页面，若页面结构或访问策略变化，需要替换这个小适配器。已知网页也可以继续直接导入。

## 兼容与升级

- 正式小说 Agent 仍是 Writer、Reviewer、Memory Keeper 三个，没有新增第四个 Agent。
- 正史数据库 `.inkflow/inkflow.db` 不迁移，小说项目用户可见目录结构不变。
- 新功能不要求额外付费模型、本地大模型或外部数据库。
- 软件更新框架不迁移小说数据；正式启用在线更新需要公开 GitHub Release 仓库或通用 HTTPS 下载源。
- Claude Code 与 TRAE 新增三个项目内技能目录；它们是工作与输出引导，不是后台服务。

## 当前边界

- VS Code 扩展可以打包为 VSIX，但发布到 Marketplace 仍需要发布者账号和令牌；0.3 构建不会擅自替用户公开发布。
- Windows 安装包尚无商业代码签名，系统可能显示未知发布者。
- 当前私密仓库不能向大众客户端匿名提供 Release；0.3 只完成更新器和界面，待公开发布仓库配置后才会真正在线分发。
- 搜索结果只是候选来源；网页的事实质量仍需用户或 Agent 按来源类型判断。
- 提问卡的选项由会话模型提出，宿主负责限制数量、追加“其他”和守住执行门禁，但不能保证每个模型都提出同样好的选项。

研究依据与设计取舍见 [0.3 调研依据](./research/v0.3-report-source.md)。
